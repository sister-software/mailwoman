**Goal:** Land the `@mailwoman/bdc` workspace: FCC BDC availability data as a layer-contract SQLite artifact (bdc.db), the `filing_landscape()` reader, and the `mailwoman_bdc_filing_landscape` MCP tool, passing the four pre-registered 2a gates.

**Spec:** `docs/superpowers/specs/2026-07-20-bdc-plausibility-design.md` (§2.1, §3.1, §3.4, §5, §6, §7-2a). Recon report resolved seven spec contradictions; decisions pre-registered below.

## Global Constraints

- No TS `enum` — `const X = {…} as const` + `type X = (typeof X)[keyof typeof X]` (repo-wide `erasableSyntaxOnly`).
- No raw `process.env` (`sister-software/no-process-globals`) — new secrets go in `core/env/schema.ts` `PrivateEnvSchema`.
- DDL via Kysely schema-builder; hot bulk INSERTs via raw prepared statements on the same `DatabaseSync` handle; `kdb.destroy()` owns close (AGENTS.md DB rules).
- Databases are sealed read-only artifacts: build to temp, seal (`sealDatabase` from `@mailwoman/core/utils`), move into place.
- Acronym casing: `BDC` whole-cap in identifiers (`createBDCAvailabilityTable`, `$BDCClient`).
- Data paths via `dataRootPath(...)` — never hardcode `/mnt/playpen/mailwoman-data`.
- Salvage rule: copy from Nexus, no provenance headers, never duplicate existing mailwoman functionality; Nexus `.js` import specifiers become `.ts`.
- Fabric boundary (spec §2.2): never ingest/derive from CostQuest Fabric; `location_id` is opaque only.

## Pre-registered decisions (resolve recon contradictions — cite in commits)

1. **`location_id` stored as TEXT** (Nexus types it `Tagged<number>` and `parseInt`s it; the input pattern is `/^\d{10}$/` so leading zeros make integer storage lossy). Populating the column is gated behind `--include-location-ids` (default **off**) until counsel question §8.1 clears — column exists either way.
2. **`sync/fcc/bdc/common.ts` is a mandatory port** — spec §5 omits it but `list-files`/`filing-dates`/`download-file`/`path-builders` all import it; it carries 6 of the ~10 enums.
3. **`geoid` decoded to string at the parse boundary** (Nexus keeps a `Uint8Array` slice). Joins `TIGERBlockTable.GEOID` (note: uppercase column).
4. **No generic `spatial.aggregate()`** — spec §3.1 presumes a verb that does not exist. `filing_landscape` is a bdc-local SQL reader over a resolved block set; generalize only when `market_size` (2b+) provides the second consumer.
5. **Promote `shortCellToInt` into `@mailwoman/spatial/h3`** — currently a private 2-liner in `build-poi.ts:397`; two call sites now exist.
6. **`$BCDClient` typo fixed to `$BDCClient` on port.**
7. **Pilot state: CA** (spec §8.3 default — demo alignment with poi.db). Fixtures are synthetic micro-CSVs, not real state files.
8. **Availability parser NOT widened for FRN/brand in 2a** (Nexus `takeAvailabilityLine` drops cols 0-2 deliberately). Provider identity (provider_id → FRN/brand) goes in a `bdc_provider` sidecar table fed from the provider file listing (`operations.ts` `collectBDCProviders` as reference), which is the 2c registry join seam.
