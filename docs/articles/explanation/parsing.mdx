# How Mailwoman turns text into address components

Why does `New York` become a locality in `apt 4b 350 5th ave new york ny 10118`, while `NY` becomes a region? Their roles depend on the surrounding address. Mailwoman uses the full line to score possible labels, applies structural rules to choose a coherent reading, and returns the labeled spans as a tree. A separate geographic lookup can later decide which real place a name identifies.

## The text supplies clues before the model decides

The runtime normalizes the input before it computes the query shape. The classifier can also adjust letter case before labeling. In the published 11.3.0 run, `input` and `normalized.normalized` both remain `apt 4b 350 5th ave new york ny 10118`, while `tree.raw` is `Apt 4B 350 5TH Ave New York NY 10118`. The returned nodes index `tree.raw`: `[19, 27)` selects `New York` from that string. [The first-parse tutorial](../start.mdx) shows the complete tree.

The query-shape stage finds clues such as word groups and postcode-shaped text. In the [trace for this input](../tutorials/inspect-a-parse.mdx), `10118` matches `us_zip`, `fr_postcode`, and `de_postcode`. Those are three possible formats for the same five characters, rather than three identified destinations. The input as a whole is classified as `structured_address`, so it takes the full parse path. A clear postcode-only or locality-only query can instead take a fast path that constructs a simpler result without neural labeling.

## The model scores roles in context

For the full path, a phrase grouper proposes boundaries and the published en-US classifier splits its input into SentencePiece pieces. The model scores component labels for those pieces while reading the surrounding text. `350` appears before `5TH Ave`, while `New York` appears between that street and `NY 10118`. Those neighbors contribute to the label scores. At this stage, the model has scored possible labels. The decoder hasn't selected the final sequence.

Each component label has a beginning form (`B-locality`), a continuation form (`I-locality`), and an outside form (`O`). A multi-piece place name can begin with `B-locality` and continue with `I-locality` instead of becoming two unrelated names. The [result schema](../reference/schema.mdx#component-tags) lists the component tags.

An optional finite-state transducer (FST) place-name index can adjust the scores of matching labels before decoding. The runtime loads the index from the weights package when it is present. A match means the text occurs as a place name in that index. It doesn't assign a place identity or coordinate. Context and the other label scores still affect the reading.

## The decoder selects spans and builds a tree

If the classifier chose each piece's highest score separately, a component could start with `I-locality` or switch tags halfway through a word. The default classifier uses Viterbi search over legal BIO transitions. The search compares complete label sequences, so a piece can take a lower individual score when that produces the better legal sequence. Word-consistency, postcode, and unit repairs can change labels after that search. The tree builder then turns the selected labels into character spans and attaches each node to a compatible parent.

For the example, the returned tree places `New York` beneath `NY` and places the street and postcode beneath the locality. The tree records what the parser read in the text. A `house_number` node doesn't show that the building exists, and a `locality` node doesn't identify which geographic record it names. A configured resolver can attach place identities and coordinates after parsing. [Why a geocode coordinate has a precision tier](./geocoding.mdx) explains that separate lookup.

The place-name index can help a close label decision only where its installed file contains a matching name. BIO transitions keep the sequence structurally valid, but they cannot make an incorrect label factually correct. A node's confidence describes its label decision, with limits discussed in [confidence and ambiguity](./confidence-and-limits.mdx). For the exact labels, spans, and source of each value, use the [parse inspection tutorial](../tutorials/inspect-a-parse.mdx) and [result schema](../reference/schema.mdx).
