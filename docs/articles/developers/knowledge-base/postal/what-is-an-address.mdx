# What an address is

## The question

You have a column of addresses and you want coordinates. It looks like a lookup: each string refers to
a place, each place has a location, and the work is finding the matching row. Then two strings that
describe the same building disagree, a third contains no street, and a fourth resolves to a town four
states away from where you expected. This page explains what an address is and why these problems keep
happening.

## The analog

An address is an instruction for reaching a delivery point, which is the smallest unit a postal service
delivers to: one letterbox, one post office box, or one loading dock behind a warehouse. The UK's unit
postcode groups about fifteen of them, and never more than a hundred
([Office for National Statistics](https://www.ons.gov.uk/methodology/geography/ukgeographies/postalgeography)).
The US Postal Service added two digits to the ZIP+4 in 1991 so that mail could be sorted "directly to
a residence or business" ([USPS](https://facts.usps.com/decoding-the-zip-code/)).

If you read an address as an instruction, its structure makes sense. It must narrow the world to one
delivery point, using words the receiving postal service recognizes, in the order that service reads
them. It does not need to describe the building, identify the owner, or place the building on a map.
`PO Box 1234, San Francisco, CA 94119` is a complete address without any geometry. The courier's work
ends at a shelf behind a counter, and the person who rents that shelf may live twenty miles away.

## Why one building carries several

Because an address is an instruction and not a property of the building, one building can have several
addresses at once, each written for a different reader.

The postal service wants the form its own address file accepts. For that reason, an office tower with
enough mail volume can have its own ZIP Code, and a tenant inside it gets a distinct ZIP+4. The last
four digits identify units as small as "a floor or group of floors in a building, a firm within a
building" ([USPS Domestic Mail Manual 602](https://pe.usps.com/text/dmm300/602.htm)). Emergency
dispatch wants the entrance a vehicle can reach. A tax assessor wants the parcel. A visitor wants the
name on the front of the building, which is why `Empire State Building` works as an address for a
tourist and fails as one for a sorting machine.

None of these is a less accurate version of one true address. They are four instructions for four
organizations. A building that touches two streets, sits on a municipal boundary, or holds two hundred
tenants will have even more of them.

## What that means for software

An address string is evidence about a place instead of an identifier for one. Two strings that disagree can
both be usable, and the disagreement is informative: it shows which system each string came from.

Mailwoman divides the work along those lines. A parse splits the string into spans and labels them,
for example as a house number or a locality, without deciding which postal system the writer had in
mind. [Component tags](../../reference/component-tags.mdx) lists the label vocabulary. Attaching
coordinates is a second pass over the labeled result. That pass reports which tier of data produced
the answer, because a rooftop point and a city centroid mean different things and would otherwise
look identical.

## What it costs

This has two consequences in production.

You cannot key a record on an address string. The same delivery point will be spelled four ways across
four source systems, and none of the four is canonical. To match records, compare components after a
parse instead of comparing text.

A geocode that returns a coordinate also does not prove that the delivery point exists. Mailwoman reads
the string you give it and matches what it can against open data. Only a postal authority's address
file, which is a licensed register of real letterboxes, can say whether mail arrives at that address.
[What Mailwoman is](../../get-started/what-mailwoman-is.mdx) explains this limit in more detail.
