# Install Mailwoman and parse your first address

By the end of this page you will have a Node script that takes a lowercase, comma-free, unit-first
address and prints it as a tree of labeled components, each with a confidence score. You do not need
an API key, a server or an account. The tutorial takes about ten minutes, most of it spent waiting
for the download.

## Prerequisites

Check these before you start. Two of them will stop you partway through if they are not met.

- **Node.js 24.18.0 or later.** The `mailwoman` package declares `engines.node` as `>=24.18.0`.
  Check yours with `node --version`.
- **About 750 MB of free disk.** Measured on Linux x64 on 2026-08-03, the three packages below plus
  their dependencies put 746 MB in `node_modules`. Of that, 500 MB is `onnxruntime-node`'s prebuilt
  binaries and 74 MB is the English model package. You pay this cost once per project, and parsing
  adds nothing to it.
- **An ESM project.** The packages are ESM-only. Either put `"type": "module"` in your
  `package.json` or name the script file `.mjs`, as this page does.

## 1. Install

```bash
npm install mailwoman @mailwoman/neural @mailwoman/neural-weights-en-us
```

Each package has one job. `mailwoman` is the pipeline and the CLI. `@mailwoman/neural` is the
runtime that executes the model. `@mailwoman/neural-weights-en-us` is the English model itself: a
39.4 MB ONNX file plus its tokenizer and lookup tables, 73.8 MB unpacked across 16 files.

None of these packages runs an install script, so the only network traffic during the install is npm
fetching tarballs.

## 2. Write the script

Save this as `parse.mjs`.

```js
import { createRuntimePipeline } from "mailwoman"
import { NeuralAddressClassifier } from "@mailwoman/neural"

const classifier = await NeuralAddressClassifier.loadFromWeights({ locale: "en-US" })
const parse = createRuntimePipeline({ classifier })

const result = await parse("apt 4b 350 5th ave new york ny 10118")

console.log("input:", result.input)
console.log("locale:", result.locale.locale)
console.log("kind:", result.kind.kind)
console.log()

function print(node, depth = 0) {
	const pad = "  ".repeat(depth)
	console.log(`${pad}${node.tag}: "${node.value}"  (confidence ${node.confidence.toFixed(2)})`)
	for (const child of node.children) print(child, depth + 1)
}

for (const root of result.tree.roots) print(root)
```

`createRuntimePipeline` is the main entry point. It connects the whole staged pipeline
(normalization, structural analysis, locale detection, phrase grouping, the model, and the resolver
if you supply one) and returns a single async function. The classifier is the only stage without a
default, because the model is a separate download. Every other stage has a production default.

The address is deliberately messy. It is lowercase, has no commas, and puts the unit in front of the
house number.

## 3. Run it

```bash
node parse.mjs
```

```
input: apt 4b 350 5th ave new york ny 10118
locale: en-US
kind: structured_address

region: "NY"  (confidence 0.91)
  locality: "New York"  (confidence 0.93)
    street: "5TH"  (confidence 0.93)
      unit: "Apt 4B"  (confidence 0.86)
      house_number: "350"  (confidence 0.91)
      street_suffix: "Ave"  (confidence 0.92)
    postcode: "10118"  (confidence 0.91)
```

On the machine used to verify this page, loading the model took 735 ms and the first parse took
402 ms. The next twenty parses on the same `parse` function averaged 7.3 ms each. Build the pipeline
once and reuse it instead of rebuilding it for each request.

## 4. Read the tree

Know three things about that output before you write code against it.

**The result is a tree.** `result.tree.roots` is an array of top-level nodes, and
each node has `tag`, `value`, `confidence`, and `children`. The nesting represents geographic
containment. `NY` contains `New York`, which contains the street and the postcode, and the street
contains the house number, the unit, and the suffix. If you want a flat record, walk the tree and
collect nodes by `tag`. The parser returns the containment structure and leaves flattening to you.

**The confidence is the model's own score, and it is not calibrated by default.** Read `0.91` as
"the model scored this span 0.91", not as "this span is right 91% of the time". A calibration fit
ships in the same weights package (`calibration.json`). To apply it, wire `createCalibrator` from
`@mailwoman/core/decoder`. The calibrator is off by default so that the parse output stays
byte-stable. On the held-out set this model is under-confident: mean confidence is 0.913 against
0.980 accuracy, and the fit reduces expected calibration error from 0.0698 to 0.0017. If you plan to
route on the score (for example, sending everything under 0.8 to human review), wire the calibrator
first. The uncalibrated score would send more addresses to review than the error rate justifies.

**Values come back repaired.** The input said `apt 4b` and the output says `Apt 4B`.
The ordinal `5th` comes back as `5TH`. If you pass the same address in mixed case with commas, the
repair step leaves the casing alone. If you need the exact characters the user typed, keep your own
copy of the input string, or read `result.input`.

Two more fields on `result` are useful later. `result.locale` records which locale the pipeline
chose, and `result.kind` records the query shape it detected (`structured_address` here, or
`postcode_only`, `po_box`, `intersection`, and others).

## What you have now

You have a parser running in your own process, without a service dependency. It turns free-text
addresses into labeled components with confidence scores you can route on. It does not produce
coordinates yet, because coordinates require a gazetteer database, which is a separate download.
