# Validate an address before you use it

**Outcome.** You have a function that rejects incomplete, malformed and weakly-read addresses, and you
know which failures it cannot catch.

On this page, validation means three checks, run in this order. Every component you require must be
present. Each component must have been read with high confidence. Each component must have a shape
that the postal system allows. Mailwoman does not check deliverability. These checks use no carrier
database and never send mail. Read [What this does not tell you](#what-this-does-not-tell-you) before
you connect this function to a checkout form.

## Prerequisites

- The library install from
  [Install and first parse](../get-started/install-and-first-parse.mdx), plus `@mailwoman/codex` for
  the postal reference tables.
- You do not need a gazetteer database for the checks. Each check uses only the parse and the
  reference tables, so none of them needs a data root. The last section adds a geocode, which does need
  one.

## 1. Flatten the parse into components

`classifier.parse()` returns a tree, because a locality contains a street and a street contains a house
number. Validation checks presence and confidence and ignores nesting, so flatten the tree first:

```js
function flatten(nodes, into = new Map()) {
	for (const node of nodes) {
		into.set(node.tag, { value: node.value, confidence: node.confidence })
		flatten(node.children, into)
	}
	return into
}
```

Each node carries a `confidence` in `[0, 1]`, aggregated across the span's tokens. The tree has no
whole-parse confidence field. It exposes only per-component scores, so you compute a row-level result
yourself. Base it on the weakest component.

## 2. Decide what "complete" means for your use

Completeness depends on what you will do with the address. A shipping label
needs a house number, and a sales-territory rollup does not. Write the list down explicitly:

```js
/** Components a US mailing address needs before you send anything to it. */
const REQUIRED = ["house_number", "street", "locality", "region", "postcode"]
```

The component names come from the schema.
[`SCHEMA.mdx`](https://github.com/sister-software/mailwoman/blob/main/docs/engineering/reference/SCHEMA.mdx)
has the full `ComponentTag` list, and [Understand a parse](../tutorials/understand-a-parse.mdx)
describes what each one holds.

## 3. Add the postal shape checks

`@mailwoman/codex` ships the postal reference tables as pure functions without runtime dependencies.
Three of them cover most of the errors a US address can have:

| Check                        | Function                       | Subpath               |
| ---------------------------- | ------------------------------ | --------------------- |
| Region is a real state code  | `isUSStateAbbreviation(value)` | `@mailwoman/codex/us` |
| Postcode has ZIP Code shape  | `isZipCode(value)`             | `@mailwoman/codex/us` |
| Street ends in a USPS suffix | `matchTrailingSuffix(name)`    | `@mailwoman/codex/us` |

Each of these checks whether a value _could_ exist. None of them checks whether it _does_. `isZipCode`
is the regular expression `^\d{5}(?:[-\s]\d{4})?$`, so `00000` passes and `2000` fails. Codex has no
per-ZIP registry by design. It is a zero-dependency reference package, and existence data is in the
gazetteer.

Other locales ship the same pair of functions under their own subpath, named with the local term
instead of a generic one: `isUkPostcode`/`normalizeUkPostcode` under `@mailwoman/codex/gb`,
`isCodePostal`/`normalizeCodePostal` under `/fr`, `isPostleitzahl`/`normalizePLZ` under `/de`. Check the
subpath's exports instead of guessing the name.
`candidateSystemsForPostcode(value)` from the package root tests a string against every shape at once
and returns the address systems that accept it. Use it to check a postcode when you do not yet know the
country.

## 4. Put it together

```js
import { isStreetDirectionalToken, isUSStateAbbreviation, isZipCode, matchTrailingSuffix } from "@mailwoman/codex/us"
import { NeuralAddressClassifier } from "@mailwoman/neural"

const classifier = await NeuralAddressClassifier.loadFromWeights({ locale: "en-US" })

/** Components a US mailing address needs before you send anything to it. */
const REQUIRED = ["house_number", "street", "locality", "region", "postcode"]

/** The floor a component's confidence has to clear before it counts as read rather than guessed. */
const MIN_CONFIDENCE = 0.8

function flatten(nodes, into = new Map()) {
	for (const node of nodes) {
		into.set(node.tag, { value: node.value, confidence: node.confidence })
		flatten(node.children, into)
	}
	return into
}

/**
 * The USPS suffix of a street name, looking past a post-directional: `Pennsylvania Ave NW` ends in `NW`, so a bare
 * trailing-token match misses the `Ave` that is the suffix.
 */
function trailingSuffixOf(streetName) {
	const tokens = streetName.split(/\s+/)
	while (tokens.length > 1 && isStreetDirectionalToken(tokens.at(-1))) tokens.pop()
	return matchTrailingSuffix(tokens.join(" "))
}

export async function validateAddress(raw) {
	const components = flatten((await classifier.parse(raw)).roots)
	const problems = []

	for (const tag of REQUIRED) {
		if (!components.has(tag)) problems.push(`missing ${tag}`)
	}

	for (const [tag, c] of components) {
		if (c.confidence < MIN_CONFIDENCE) problems.push(`low confidence on ${tag} (${c.confidence.toFixed(3)})`)
	}

	// Shape checks from the postal reference tables. Each one asks "could this exist", never "does this exist".
	const region = components.get("region")
	if (region && !isUSStateAbbreviation(region.value)) problems.push(`${region.value} is not a US state abbreviation`)

	const postcode = components.get("postcode")
	if (postcode && !isZipCode(postcode.value)) problems.push(`${postcode.value} is not ZIP Code shaped`)

	const street = components.get("street")
	if (street && !components.has("street_suffix") && !trailingSuffixOf(street.value)) {
		problems.push(`${street.value} carries no recognized USPS street suffix`)
	}

	return { raw, ok: problems.length === 0, problems, components: Object.fromEntries(components) }
}
```

The directional strip in `trailingSuffixOf` is easy to miss. `Pennsylvania Ave NW` ends in `NW`, so a
direct trailing-suffix lookup returns no match and rejects a correct address. Post-directionals come
after the suffix, so strip them before the lookup.

## Verify

```bash
node validate.mjs \
  "1275 Pennsylvania Ave NW, Washington, DC 20004" \
  "42 Nonexistent Ln, Zzyzx Falls, ZZ, 00000" \
  "800 F St NW, Washington, DC 2000" \
  "Suite 400" \
  "1275 Pennsylvania Avenue Northwest, Washington"
```

```
ok    1275 Pennsylvania Ave NW, Washington, DC 20004
FAIL  42 Nonexistent Ln, Zzyzx Falls, ZZ, 00000
        low confidence on region (0.462)
        ZZ is not a US state abbreviation
FAIL  800 F St NW, Washington, DC 2000
        2000 is not ZIP Code shaped
FAIL  Suite 400
        missing house_number
        missing street
        missing locality
        missing region
        missing postcode
        low confidence on unit (0.038)
FAIL  1275 Pennsylvania Avenue Northwest, Washington
        missing house_number
        missing locality
        low confidence on region (0.507)
        low confidence on postcode (0.724)
        Washington is not a US state abbreviation
        1275 is not ZIP Code shaped
```

The last failure is the most informative. `1275 Pennsylvania Avenue Northwest, Washington` has no state
and no ZIP Code, so the parse assigned `Washington` to `region` at 0.507 and `1275` to `postcode` at
0.724. Both assignments are wrong, and both scored low. The confidence check and the shape check each
caught the same defect independently.

## What this does not tell you

These two addresses pass every check above:

```
ok    99999 Pennsylvania Ave NW, Washington, DC 20004
ok    1275 Pennsylvania Ave NW, Chicago, IL 60606
```

There is no 99999 Pennsylvania Avenue, and 1275 Pennsylvania Avenue is in Washington. The second
address places it in Chicago.
Both addresses are complete, read with high confidence, and correctly shaped. Neither exists.

The checks cannot close this gap. Presence, confidence and shape are properties of the string.
Existence is a property of the world, and checking it requires a record to match against, which is
what geocoding provides. `resolution_tier` on a geocode result identifies the finest record that
matched:

```bash
for a in "1275 Pennsylvania Ave NW, Washington, DC 20004" "99999 Pennsylvania Ave NW, Washington, DC 20004"; do
  npx mailwoman geocode "$a" | jq -c '{resolution_tier, uncertainty_m, lat, lon}'
done
```

```json
{"resolution_tier":"address_point","epistemic_status":"observed","uncertainty_m":1,"lat":38.89566505262116,"lon":-77.02925468482408}
{"resolution_tier":"admin","epistemic_status":"observed","uncertainty_m":null,"lat":38.904831,"lon":-77.016216}
```

That run had `candidate.db` plus the DC address-point database on disk (the setup
[Improve geocode precision](../tutorials/improve-geocode-precision.mdx) builds). Without that file, both
rows return `admin` and the check below cannot distinguish them. The precision data is what makes this
test meaningful.

`address_point` means a rooftop record for that house number matched. `admin` means no level finer than
the city matched, and the returned coordinate is the city centroid. Adding
`result.resolution_tier === "address_point"` to your check changes its meaning from "well-formed" to
"we hold a record for it". That is the closest this system comes to checking existence.

A matching record still does not establish deliverability. A rooftop record says a structure was
surveyed at that address. It does not say that mail is accepted there, that the unit number is right,
or who the occupant is. No part of Mailwoman contacts a carrier. If you need to know whether a parcel
will arrive, use a postal carrier's address-verification service.

## Limits

- **Shape checks are per-country, and you must pick the country.** `isZipCode` rejects a valid GB
  postcode. Choose the codex subpath from the parsed country, or use `candidateSystemsForPostcode`
  when the country is unknown.
- **Codex holds no existence tables.** It has neither a ZIP-to-state cross-check nor a street registry.
  The `ZipCodePrefixAbbreviationMap` it ships maps a ZIP Code's first digit to a band of states. It is
  a hint, not a lookup.
- **A raw confidence near 0.9 does not mean 90% correct.** The scores on this page are uncalibrated,
  and their spread on clean input is narrow. Read
  [Tune confidence thresholds](./tune-confidence-thresholds.mdx) before you pick `MIN_CONFIDENCE` for
  production. The 0.8 used here is for demonstration and is not a recommendation.
- **`street_suffix` is sometimes its own component and sometimes part of `street`.** The check above
  handles both cases, and any street-shape check you write must handle both.
