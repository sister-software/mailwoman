# Node library API

This page describes the principal Node library calls. A parser from `createParser` parses an address into a labeled tree. A geocode also requires a resolver and geographic databases. [Parse and geocode result schema](./schema.mdx) defines the result fields, tags, coordinate tiers, and provenance values.

## Imports

| Import                       | Public entry points covered here                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `mailwoman`                  | `createParser`, the tree readers below, and the `AddressNode` and `PipelineResult` types |
| `mailwoman/runtime-pipeline` | `createRuntimePipeline`                                                                  |
| `mailwoman/geocode`          | `parseForGeocode`, `geocodeAddress`, `geocodeStream`, `createRegionDatabaseProvider`     |
| `@mailwoman/neural`          | `NeuralAddressClassifier`                                                                |
| `@mailwoman/core/decoder`    | `createCalibrator`                                                                       |

The `mailwoman` package installs the classifier and the en-US model, so a parse needs no other package.

## Parse calls

```ts fragment
function createParser(options?: ParserOptions): Promise<Parser>

interface Parser extends AsyncDisposable {
	parse(raw: string, runOpts?: PipelineOpts): Promise<PipelineResult>
	readonly scope: ServiceRegistry
}
```

`createParser` loads a parser with the options below, en-US when you state none. The parser keeps its model loaded for every `parse` call, and the caller owns it: the package holds zero parser of its own between calls. `await using` releases the model when the scope ends, and a long-lived service keeps one parser and calls `await parser[Symbol.asyncDispose]()` at shutdown:

```ts fragment
await using parser = await createParser({ locale: "en-US", machinePreferences: "none" })
const result = await parser.parse("10118")
```

An input in another script, such as Chinese or Japanese text, routes to that script's model when its weights package is installed. Otherwise the parser logs one warning and parses it with the locale's model.

| Parser option        | Type and default                         | Effect                                                                    |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| `locale`             | BCP-47 locale; `en-US`                   | Selects the weights package of the primary model.                         |
| `dataRoot`           | path, absent                             | Overlays the installed weights with the data root's `weights/` directory. |
| `weightsCacheRoot`   | path, absent                             | Loads the weights only from this cache.                                   |
| `machinePreferences` | `auto`, `none`, or preferences; `auto`   | Supplies host locale preferences when the caller and input provide none.  |
| `caseNormalization`  | `title-case` or `preserve`; `title-case` | Sets the default case treatment for calls.                                |
| `placerCountryUse`   | `filter` or `prior`; `filter`            | Sets how a confident coarse country guess constrains resolution.          |
| `poiQueryKind`       | `extract` or `none`; `extract`           | Detects point-of-interest queries.                                        |
| `scope`              | `ServiceRegistry`, absent                | Reuses the classifier a geocode process scope already holds.              |

These functions read the tree a parse returns:

| Function                 | Returns                                                                                         |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| `decodeAsJSON(tree)`     | One value per tag. The [neural classifier](#neural-classifier) section describes its options.   |
| `decodeAsTuples(tree)`   | `[tag, value]` pairs in source order, repeated tags included.                                   |
| `groupTuplesByTag(tree)` | A `Map` from each tag to all of its values, in source order.                                    |
| `flattenTreeNodes(tree)` | Every node in source order with its tag, value, span, score and resolved place fields.          |
| `decodeAsOutline(tree)`  | Text with one node per line, `tag [start, end): "value"`, each child indented under its parent. |
| `walkNodes(roots)`       | A generator over every node in depth-first order, each parent before its children.              |

`console.table(flattenTreeNodes(result.tree), ["tag", "value", "start", "end"])` prints the components with their spans.

## Runtime pipeline

```ts fragment
interface RuntimePipeline extends AsyncDisposable {
	(raw: string, runOpts?: PipelineOpts): Promise<PipelineResult>
}

function createRuntimePipeline(opts?: CreateRuntimePipelineOpts, scope?: { parent?: ServiceRegistry }): RuntimePipeline
```

`mailwoman/runtime-pipeline` exports the factory that `createParser` builds on. Use it to supply your own classifier, a resolver, or a POI database. The factory returns a parse function synchronously. The returned function runs the async pipeline.

The pipeline owns what it loads for an `auto` stage: the bundled coarse placer, the street index and the POI database. It loads each on the first call and closes it when the pipeline is disposed, so hold a pipeline with `await using` or call its `Symbol.asyncDispose` after the last parse. A process holds no shared copy of these. A caller that builds several pipelines calls `registerRuntimePipelineServices(registry)` on one `ServiceRegistry` from `async-init` and passes `{ parent: registry }` to each, so the registry loads each default once and closes it at its own disposal. An omitted classifier leaves the structural stages available, but a neural classifier is required for a labeled parse. The pipeline can add resolved places to the tree when `resolver` is supplied.

The following factory options are the settings a caller uses to choose the stages and their defaults. `CreateRuntimePipelineOpts` also exposes stage-replacement callbacks and prior controls for custom pipelines. Read the exported TypeScript declaration for those advanced fields.

| Factory option        | Type and default                                       | Effect                                                                                 |
| --------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `classifier`          | classification stage, absent                           | Supplies labeled address spans. The published neural classifier implements this stage. |
| `resolver`            | `Resolver`, absent                                     | Resolves parsed places when a geographic database backs it.                            |
| `fst`                 | `auto`, `none`, or matcher; `auto`                     | Loads the classifier's gazetteer matcher when available.                               |
| `streetMorphology`    | `auto`, `none`, or matcher; `auto`                     | Supplies street-form evidence when a matcher is available.                             |
| `anchorRegions`       | `auto`, `none`, or lookup; `auto`                      | Supplies the admin ancestry of an anchored postcode beside an `auto` gazetteer.        |
| `streetEvidence`      | `auto`, `none`, or evidence index; `auto`              | Supplies a street reranking index when available.                                      |
| `placeCountry`        | `auto`, `none`, or function; `auto`                    | Supplies the coarse country guess.                                                     |
| `machinePreferences`  | `auto`, `none`, or preferences; `auto`                 | Supplies host locale preferences when the caller and input provide none.               |
| `poiQueryKind`        | `extract`, `none`, or `{ poiDatabasePath }`; `extract` | Detects point-of-interest queries. The object form also opens a lookup for execution.  |
| `caseNormalization`   | `title-case` or `preserve`; `title-case`               | Sets the default case treatment for calls.                                             |
| `placerCountryUse`    | `filter` or `prior`; `filter`                          | Sets how a confident coarse country guess constrains resolution.                       |
| `hardCountrySafelist` | `ReadonlySet<string>`, artifact or built-in default    | Replaces the countries eligible for a hard country filter.                             |

`Parser.parse` and the function `createRuntimePipeline` returns accept these `PipelineOpts` fields on each call. A per-call value for `caseNormalization`, `placerCountryUse`, or `hardCountrySafelist` replaces the factory value for that call.

| Per-call option       | Type and default                                               | Effect                                                                              |
| --------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `locale`              | BCP-47 locale, detected when omitted                           | Supplies a locale hint.                                                             |
| `userLocation`        | coordinate, country, or region and country. Absent by default. | Supplies the resolver with the caller's location.                                   |
| `inputMode`           | `auto`, `fragmented`, or `formatted`; `auto`                   | Selects the input register from the query kind when `auto`.                         |
| `forceFullPipeline`   | `boolean`, false                                               | Disables postcode and locality fast paths. Point-of-interest routing still applies. |
| `resolveOpts`         | `ResolveOpts`, absent                                          | Passes resolver-specific options through.                                           |
| `caseNormalization`   | `title-case` or `preserve`; factory default                    | Sets letter-case treatment.                                                         |
| `placetypePair`       | `inherit`, `off`, or prior object; `inherit`                   | Selects the placetype-pair prior.                                                   |
| `placerCountryUse`    | `filter` or `prior`; factory default                           | Sets coarse country-guess use.                                                      |
| `hardCountrySafelist` | `ReadonlySet<string>`, factory default                         | Replaces the hard-country filter set.                                               |
| `signal`              | `AbortSignal`, absent                                          | Allows cancellation of the call.                                                    |

`PipelineResult` includes `input`, `normalized`, `queryShape`, `locale`, `kind`, `phraseProposals`, `tree`, `poiIntent`, `timing`, `faults`, `intentMarkers`, and `path`. `faults` records stage failures that the coordinator caught and continued past. An empty `faults` array means no stage faulted in that call. The [result schema](./schema.mdx#parse-result) gives each field's type and meaning.

## Neural classifier

```ts fragment
NeuralAddressClassifier.loadFromWeights(
  ...args: Parameters<typeof loadClassifierFromWeights>
): Promise<NeuralAddressClassifier>
```

`loadFromWeights` loads a model for one locale. The published en-US exercise installs `@mailwoman/neural-weights-en-us@11.0.0` and passes `{ locale: "en-US" }`. The loader also accepts explicit `modelPath`, `tokenizerPath` or `charVocabPath`, `modelCardPath`, `tier`, and `cacheRoot` options. `tier` is `server` by default; `pocket` omits lexicons and keeps the postcode anchor. The full loader type is `ResolveWeightsOpts` plus inference and diagnostic options in `packages/neural/lib/classifier/loader.ts`.

| Method                         | Return type                                      | Projection                                                                                                                 |
| ------------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `parse(text, opts?)`           | `Promise<AddressTree>`                           | Nested labeled tree.                                                                                                       |
| `parseJSON(text, opts?)`       | `Promise<Partial<Record<ComponentTag, string>>>` | One string per retained tag. With serialization options, the result can also contain `unknown` and `dropped` arrays.       |
| `parseTuples(text, opts?)`     | `Promise<Array<[ComponentTag, string]>>`         | Source-ordered tag and value pairs, including repeated tags. With `includeUnknown`, a tuple's tag can also be `"unknown"`. |
| `parseXML(text, opts?)`        | `Promise<string>`                                | XML serialization.                                                                                                         |
| `parseWithLogits(text, opts?)` | `Promise<ParseWithLogitsResult>`                 | Parsed tree, raw model logits from before priors and repairs, and piece offsets.                                           |
| `traceParse(text, opts?)`      | `Promise<NeuralParseTrace>`                      | Serializable decode trace. The trace omits `opts.calibrate`.                                                               |

Each method takes `ParseOpts` where shown. Common settings include `inputMode`, `caseNormalization`, `queryShape`, `fst`, `calibrate`, and `placetypePair`. Direct classifier calls have their own defaults and omit the runtime pipeline's surrounding stages. Use `createParser` for the complete parse path and the classifier methods when the direct model result or logits are needed.

`decodeAsJSON(tree, opts?)` flattens an `AddressTree` to one value per tag. Its `includeUnknown` and `includeDropped` options add diagnostic arrays, including empty arrays when requested and no spans qualify. When two spans have the same tag, the projection keeps the grounded span first, then uses document order for administrative and postal tags or label confidence for other tags. The `dropped` array identifies a discarded value and the value that took its slot. Read `tree` when repeated spans or tree nesting matter.

## Geocode and batch calls

```ts fragment
function parseForGeocode(
	input: string,
	deps: Pick<
		GeocodeDeps,
		| "classifier"
		| "normalizeInput"
		| "caseNormalization"
		| "inputMode"
		| "fst"
		| "streetMorphology"
		| "streetMorphologyPrior"
		| "anchorRegions"
		| "venueHead"
		| "venueHeadOpts"
	>
): Promise<AddressTree>
function geocodeAddress(input: string, deps: GeocodeDeps): Promise<GeocodeResult>
function geocodeStream(
	records: AsyncIterable<SourceRecord> | Iterable<SourceRecord>,
	opts: GeocodeStreamOptions
): AsyncIterableIterator<SourceRecord>
```

Import these functions from `mailwoman/geocode`. `GeocodeDeps` requires a `classifier`, a `resolver` and a `placeCountry`. `placeCountry` is the coarse country router behind the soft country prior, or `"none"` for no prior. `geocodeAddress` loads no router by itself: `loadBundledPlaceCountry()` from `mailwoman/default/placer` loads the bundled one, and a caller loads it once and passes the same function to every call. A call that states neither throws a `TypeError`. A geocode also requires geographic data behind the resolver. The optional `databases`, `nationalDatabases`, and `osmDatabases` fields select additional region and address-point layers. `parseForGeocode` accepts the parse-related subset of `GeocodeDeps` and returns a tree without running the full coordinate cascade. `createRegionDatabaseProvider(factory, dataRoot, catalog?)` returns a disposable provider of each region's address-point and interpolation databases, keyed by the region's ISO 3166-2 code, such as `US-TX`. It reads the address-layer manifest of every country that has one under the data root, then the release manifest and the per-state database paths of <Country code="US" />, before it returns. A region with no file answers an empty bundle, and a listed file that can't be opened throws. It uses the supplied `catalog` snapshot when present and reads the active selection otherwise. Its factory supplies the SQLite lookup classes.

`geocodeStream` starts workers with these `GeocodeStreamOptions` fields. Each worker builds one geocode session from the serializable `geocode` configuration, the session `mailwoman geocode` builds. When `geocode.country` is absent, the worker uses `"US"` as the resolver's default country. A record with `raw` input and a mapped address receives the geocode result in its `address` field, or `null` when the geocoder returns no address. A record without `raw` input or a mapped address passes through unchanged. The stream yields records in worker completion order. A caller that needs input order must retain each record's input position and reorder the results by its `SourceRecord.id`.

| Stream option | Type and default                                | Effect                                                                                       |
| ------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `mapping`     | `ColumnMapping`, required                       | Recomputes each record's address in the worker. Use the mapping used to normalize the input. |
| `geocode`     | `GeocodeStreamConfig`, required                 | Supplies `wofDBPath`, `dataRoot`, and `locale`; `country` is optional.                       |
| `concurrency` | `number`; `Math.min(4, availableParallelism())` | Sets the worker pool size. Each worker loads the model and opens the database.               |
| `batchSize`   | `number`; `32`                                  | Sets the number of records per dispatched batch.                                             |
| `worker`      | `string` or `URL`; compiled geocode worker      | Replaces the worker module. The source uses this option for tests.                           |

`GeocodeResult` separates parsed `components` from `lat`, `lon`, `resolution_tier`, `epistemic_status`, and `coordinate_source`. The [result schema](./schema.mdx#geocode-result-and-provenance) defines those fields. The geocoding calls and stream were checked against the published 11.0.0 declarations and repository source, without a geographic database, so this page records no geocoding response or batch output. [Geocode a file of addresses](../tutorials/geocode-a-file.mdx) shows executed geocodes.

## Confidence calibration

```ts fragment
function createCalibrator(table: CalibrationTable | CalibrationBin[]): Calibrator
type Calibrator = (rawConfidence: number) => number
```

`createCalibrator` from `@mailwoman/core/decoder` makes a function from a supplied calibration table. It sorts the bins by center, interpolates between adjacent centers, and clamps inputs outside the table to its endpoint values. Pass that function as `ParseOpts.calibrate` on a direct classifier call. The default parse path doesn't apply a calibration table. The caller supplies a table fitted for the model being used. This function doesn't select one.

## Errors and absence

| Call or field                                                                                                          | Observed or declared behavior                                                                                                                                                       | Caller action                                                               |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `loadFromWeights({ modelPath: "/tmp/mailwoman-r01-missing.onnx", tokenizerPath: "/tmp/mailwoman-r01-missing.model" })` | Published 11.0.0 threw `Explicit modelPath does not exist: /tmp/mailwoman-r01-missing.onnx`.                                                                                        | Supply an existing model path or install the locale's weights package.      |
| `createCalibrator([])`                                                                                                 | Published 11.0.0 threw `createCalibrator: empty calibration table`.                                                                                                                 | Supply at least one calibration bin.                                        |
| `geocodeAddress`                                                                                                       | Its declaration and source allow a fatal parse or resolve error to reject the promise. The exact error text depends on the failing dependency and is unknown from this page's runs. | Inspect the classifier, resolver, and data paths for the failing call.      |
| `PipelineResult.faults`                                                                                                | The coordinator returns caught stage failures in this array. The executed example returned an empty array.                                                                          | Inspect each reported stage, name, and message before using a partial tree. |

## Example: parse one address

The example needs <NodeRequirement /> and an <ECMAScriptModuleProject />. Install the package:

```sh npm2yarn
npm install mailwoman
```

Save this complete file as `library.ts`:

```ts
import { createParser, decodeAsJSON } from "mailwoman"

await using parser = await createParser()

const result = await parser.parse("apt 4b 350 5th ave new york ny 10118")

console.log("kind:", result.kind.kind)
console.log("path:", result.path)
console.log("faults:", result.faults.length)
console.table(decodeAsJSON(result.tree))
```

Run `node library.ts`. The script prints this output on Linux x64:

```text
kind: structured_address
path: full
faults: 0
┌───────────────┬────────────┐
│ (index)       │ Values     │
├───────────────┼────────────┤
│ region        │ 'NY'       │
│ locality      │ 'New York' │
│ postcode      │ '10118'    │
│ street        │ '5TH'      │
│ unit          │ 'Apt 4B'   │
│ house_number  │ '350'      │
│ street_suffix │ 'Ave'      │
└───────────────┴────────────┘
```
