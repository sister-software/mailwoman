# Packages and runtime

The first-parse exercise installs one package. The package roles and sizes below were checked against published 11.3.0. The runtime path rules retain their published 11.0.0 source baseline until the geographic-data rebuild can be checked. [The library reference](./library.mdx) gives callable signatures, options, and result types. [Limits and release status](/product/limits-and-status) distinguishes downloadable data from installed and evaluated coverage.

The [data and locales reference](./data-and-locales.mdx) lists bundle dependencies, model families, and scope classifications.
The [CLI reference](./cli.mdx) lists the current checkout's generated command and flag tables with selected published 11.0.0 checks.

## Install for a first parse

```sh npm2yarn
npm install mailwoman
```

The published `mailwoman@11.3.0` manifest depends on `@mailwoman/neural` and `@mailwoman/neural-weights-en-us`. The `mailwoman` entry point exports `createParser` and the tree readers used in the [first-parse tutorial](../start.mdx). Install a scoped package directly when your application imports its own entry point, as the [record-check guide](../guides/validate-records.mdx) does for `@mailwoman/codex`.

These package roles and import surfaces were checked against the 11.3.0 release. A geocoding call also needs a resolver and geographic data. The [library reference](./library.mdx#geocode-and-batch-calls) gives the resolver interface and call signature.

Mailwoman requires <NodeRequirement />. These are the patched release floors from the [November 2026 Node.js security release](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases/).

The manifest also declares `type: "module"`. The examples on these pages are TypeScript files that Node runs directly, from a project whose `package.json` sets `"type": "module"`. The published en-US weights package and its bundled model card both identify version 11.3.0. The bundled `calibration.json` still identifies model version 5.3.0, so it doesn't establish an accuracy mapping for the installed model. [Confidence and limits](../explanation/confidence-and-limits.mdx) explains that distinction.

## Runtime variables and path precedence checked with 11.0.0

| Variable                 | Published 11.0.0 behavior                                                                                                                                                                                                                                                     |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAILWOMAN_DATA_ROOT`    | Root for downloaded data and runtime artifacts. The default is the platform data directory.                                                                                                                                                                                   |
| `MAILWOMAN_CANDIDATE_DB` | Pins a candidate database path. Candidate resolution checks an explicit call option first, then this variable, then the active selection, then the conventional path under the data root. A missing pinned file yields no candidate path; `none` selects the WOF FTS backend. |
| `MAILWOMAN_WOF_DB`       | Supplies comma-separated WOF admin database paths when `--resolve-db` is absent. Without either pin, geocoding reads the active selection's WOF extracts, then the conventional paths under the data root when the selection lists none.                                      |
| `MW_LOCALE`              | Supplies an environment locale hint to the runtime pipeline when a caller doesn't supply a locale.                                                                                                                                                                            |
| `MAILWOMAN_MODEL_CARD`   | Supplies the first model-card path tried by the native server's health report. A missing or unreadable file falls back to the installed en-US weights card, then the repository copy.                                                                                         |

`MAILWOMAN_DATA_ROOT` selects a directory, while `MAILWOMAN_CANDIDATE_DB` and `MAILWOMAN_WOF_DB` pin database paths. An explicit database path takes precedence over its environment variable where the published resolver accepts one. A missing candidate pin can leave the WOF FTS backend available. The geocoder skips missing pinned WOF paths and reports an error if none remains. An unreadable artifact listed by the active selection raises an error. Check resolved paths with `mailwoman doctor`. The [release status](/product/limits-and-status) records the verification host's installed-data state. Check the data root of each deployment separately.

## Checked file sizes

These are local apparent file and directory sizes from a published 11.3.0 installation on Linux x64, measured 26 November 2026. `du -sb` measured each installed package directory separately, and `stat -c %s` measured the model file. The values describe the listed directory or file in this installation. They exclude the rest of `node_modules` and any downloaded geocoding database.

| Installed path                                            | Method       |      Bytes |
| --------------------------------------------------------- | ------------ | ---------: |
| `node_modules/mailwoman`                                  | `du -sb`     | 20,438,302 |
| `node_modules/@mailwoman/neural`                          | `du -sb`     |  1,702,682 |
| `node_modules/@mailwoman/neural-weights-en-us`            | `du -sb`     | 69,117,825 |
| `node_modules/@mailwoman/neural-weights-en-us/model.onnx` | `stat -c %s` | 29,831,448 |

The total size of a clean install containing only the three first-parse packages hasn't been measured for this page. This page doesn't measure runtime memory, browser download size, or server capacity. [Run the Mailwoman HTTP server](../tutorials/run-a-server.mdx) reports one resident-memory measurement from one Linux host, and [Parse an address in a browser](../guides/parse-in-browser.mdx) reports one browser transfer size. The bundle registry's declared data estimates are on [limits and release status](/product/limits-and-status).

On 26 November 2026, `npm view <package>@11.3.0 dist.unpackedSize` returned the same three package-directory byte values shown above. This registry metadata checks the package contents separately from the local `du -sb` run. The `model.onnx` value comes from the local file measurement. The registry metadata doesn't report that file's size.
