# Coverage by jurisdiction

This page lists what the repository holds for each of 259 jurisdictions: every ISO 3166-1 alpha-2
code in `@mailwoman/codex/country`, plus the non-ISO operational codes that `@mailwoman/codex/postal-regimes`
defines. A second table counts the same holdings over each country grouping in `@mailwoman/registry/groupings`.
The page states holdings. A [support promise](./support.mdx) states what Mailwoman guarantees.

Corpus counts were taken over `0.8.22-retention-overlay`, cached 2026-11-24T04:19:01.452Z, 889,226,116 rows.
**Admitted by** shows each shipped graph whose training config admits the jurisdiction. Admission is per
graph, and 4 jurisdictions (`JP`, `CN`, `KR`, `TW`) are admitted by more than one, so the column reads the union
of `scope.config.json`'s registered configs rather than any one of them. `packages/corpus/data/training-configs/v7.2.0-address-systems-60k.yaml`
is the one `censusCoverage` read for its own mismatch findings.

That config declares a different corpus version from the one the census counted, so a row count
here describes the counted corpus rather than the one that config trains on. A zero therefore states
what the counted corpus holds rather than establishing that the source has none.

## Columns

**Corpus rows** counts rows in the training corpus. **Street rows** counts those with a `street`
or `house_number` label. Those rows teach an address rather than a name.
A jurisdiction can hold rows while its street-row count reads 0. The largest such jurisdiction, `ML`, reads 24,811 and 0.

**Address-form rows** counts train rows written in the jurisdiction's own address form: a span labeled
`street`, a `street_*` affix or `house_number`, or one of the block-address labels `block`, `sub_block` and
`building_number` that a block-addressed locale writes in place of a street. It reads every training corpus a
shipped graph trains on, the corpus above plus `v8-cjk-regs-2026-09-08` (the `cjk` graph, label set `stage3-cjk`), so a Japanese or Korean address that its own graph trains on counts here though the street-row column omits it.

**Cited layout** reads `cited` when the address layout the codex renders for the jurisdiction cites a primary
document (`layoutCitationForCountry` in `@mailwoman/codex/address/layouts`).

**Held out** reads the held-out address rows sampled for the jurisdiction as confirmation / development: the
collections the development and confirmation roles of release specification version 14, the newest committed,
score. Each count is the address cells of the collection's own manifest. A place-name row isn't counted, and `—`
means no collection of either role samples an address row. The collections read:

- development: `heldout-dev-v0.8.18@771811f7a5a8e4da` (`corpus/heldout/heldout-dev-v0.8.18.v4.json` under the data root)
- development: `heldout-dev-v0.8.19-probes-r2@dd560a53b897dbca` (`corpus/heldout/heldout-dev-v0.8.19-probes-r2.v2.json` under the data root)
- development: `heldout-dev-v0.8.21@7f9dcfb6572d4bf9` (`corpus/heldout/heldout-dev-v0.8.21.json` under the data root)
- confirmation: `heldout-confirm-v0.8.22b@35005b713649d486` (`corpus/heldout/heldout-confirm-v0.8.22b.json` under the data root)
- confirmation: `heldout-confirm-v0.8.22b-capabilities@6d55f1bee295a4ed` (`corpus/heldout/heldout-confirm-v0.8.22b-capabilities.json` under the data root)
- confirmation: `heldout-confirm-v0.8.22-probes@cbbe8ed53c10e55d` (`corpus/heldout/heldout-confirm-v0.8.22-probes.json` under the data root)

**Admission** is `country_weights` in the training config, a hard filter. A code absent from it
trains on no rows whatever the corpus holds. A code present in it with no corpus row trains on
no rows either, by the other route.

**Gazetteer** counts admin places available to resolve, and `rooftop` marks the 2
jurisdictions whose rooftop database a consumer can obtain.
Every other rooftop database is build-local.

A **weights package** can exist for a jurisdiction no graph was trained on. Most packages are data-only
overlays that share the model graph of `@mailwoman/neural-weights-en-us` or
`@mailwoman/neural-weights-cjk`.

**Board** reads checking rows over all the rows present. A checking row has `status: pass`, and
any other row only tracks. A jurisdiction reading
`—` has no board row. That jurisdiction is unmeasured rather than failing. The board is the two-letter
country directories under `gauntlet/cases/`, so a sweep row under `generalization/` isn't a board row.

**Promise** is the deepest [support promise](./support.mdx) for the jurisdiction, in any input language and
script.

**Groupings** lists the country groupings the jurisdiction belonged to on 2026-11-24, by grouping ID.

## Separately modelled postal jurisdictions

A postal regime is a way of writing an address that doesn't follow its ISO code's own hierarchy.
Each row states what the repository models rather than what the regime is.

| --------------------------------------------- | ------------------ | ---------------------------------- | --------- |

### A corpus row whose country isn't a jurisdiction

`XK` is an operational code the register enumerates, so it holds a row in the table above. `ZZ` holds none:
it is the ISO 3166-1 user-assigned range, the register enumerates no jurisdiction for it, and
`mailwoman data coverage` reports its rows under `countryLess` rather than as a jurisdiction. A reader
counting the census's countries mustn't count it as one.

- `ZZ` — 4,678 rows, 0 street. The ISO 3166-1 user-assigned range. In `v0.6.0-register-surface` these are bare place names from the retired `synth-fragment` recipe, every one `locale: und`. Measured 2026-09-28 against the candidate gazetteer: 3,115 resolve to exactly one country, 1,646 to several, and 4 to none. An assembly can attribute the 3,115 to their country. The other 1,650 stay country-less because the gazetteer doesn't settle them (#2358).
