# Point a Nominatim, Photon or libpostal client at Mailwoman

Use this procedure when an application already calls Nominatim, Photon or a libpostal REST service, and you want it to call Mailwoman with as few changes as possible. Each compatibility package runs its own server with that service's routes. Change the client's base URL, then compare the fields your client reads with the responses on this page.

## Prerequisites

Use Node.js 24.22.1 or a later 24.x release. Install the compatibility package for your client next to the parser packages:

```bash
npm install mailwoman@11.0.0 @mailwoman/neural@11.0.0 @mailwoman/neural-weights-en-us@11.0.0 @mailwoman/nominatim@11.0.0 @mailwoman/photon@11.0.0 @mailwoman/libpostal@11.0.0
```

The Nominatim and Photon servers geocode, so they need the global place candidates, plus address points for the places your client queries. The examples query Washington, DC:

```bash
export MAILWOMAN_DATA_ROOT="$HOME/mailwoman-data"
mkdir -p "$MAILWOMAN_DATA_ROOT"
npx mailwoman data pull candidate
npx mailwoman data pull us --only us-dc
```

The libpostal server only parses text and needs no geographic data. The responses below were captured on Node.js 24.22.1 with local builds of these bundles that are newer than the 11.0.0 registry entries.

## Nominatim clients

Start the server on the port your client will call:

```bash
npx nominatim serve --port 7803 --host 127.0.0.1 --candidate-db "$MAILWOMAN_DATA_ROOT/db/wof/candidate.db"
```

It prints the routes it serves: `GET /search`, `GET /reverse`, `GET /lookup`, `GET /status` and `GET /openapi.json`. Point the client's base URL at `http://127.0.0.1:7803`.

A free-text search with `format=jsonv2` and `addressdetails=1`:

```bash
curl --get http://127.0.0.1:7803/search --data-urlencode "q=1600 Pennsylvania Ave NW, Washington, DC 20500" --data-urlencode "format=jsonv2" --data-urlencode "addressdetails=1"
```

`/lookup` is not implemented and returns status 501:

```bash
curl -i "http://127.0.0.1:7803/lookup?osm_ids=W5013364"
```

```http
HTTP/1.1 501 Not Implemented
content-type: application/json

{"error":"this engine does not implement lookup"}
```

Only the status line, content type and body of that response are shown. `/reverse` needs a Who's On First admin gazetteer, and the data bundles do not include one. [Reverse-geocode a coordinate](./reverse-geocode.mdx) describes how to build one. Without it, `/reverse` returns status 200 with the body `null`:

```bash
curl "http://127.0.0.1:7803/reverse?lat=38.8977&lon=-77.0365&format=jsonv2"
```

```json
null
```

With an admin gazetteer in the data root, the same request returned `"display_name":"White House Grounds, Northwest Washington, Washington, District of Columbia, District of Columbia, United States"` and no `address` object. `/status?format=json` returns `"status":0,"message":"OK"` with a `mailwoman.artifacts` list that identifies each database the server opened.

## Photon clients

Start the server and point the client at it:

```bash
npx photon serve --port 7804 --host 127.0.0.1 --candidate-db "$MAILWOMAN_DATA_ROOT/db/wof/candidate.db"
```

It serves `GET /api`, `GET /reverse` and `GET /openapi.json`. A search:

```bash
curl --get http://127.0.0.1:7804/api --data-urlencode "q=1600 Pennsylvania Ave NW, Washington, DC 20500" --data-urlencode "limit=1"
```

```json
{
	"type": "FeatureCollection",
	"features": [
		{
			"type": "Feature",
			"geometry": { "type": "Point", "coordinates": [-77.03654697024702, 38.89767510742324] },
			"properties": {
				"osm_key": "place",
				"osm_value": "house",
				"type": "house",
				"city": "Washington",
				"state": "District of Columbia",
				"postcode": "20500",
				"country": "United States",
				"countrycode": "us",
				"housenumber": "1600",
				"street": "Pennsylvania Ave NW",
				"mailwoman": { "coordinate_source": { "source": "overture:NAD", "release": "2026-05-20.0" } }
			}
		}
	],
	"engine": {
		"name": "mailwoman",
		"version": "11.0.0",
		"license": "AGPL-3.0-only",
		"license_url": "https://mailwoman.post/license",
		"notice": "mailwoman is licensed AGPL-3.0-only: modified or network-served copies must offer their source. A commercial license waives that obligation."
	}
}
```

Check these differences against your client:

- Feature `properties` have `osm_key`, `osm_value`, `type`, the address fields, `country` and `countrycode`. They have no `osm_id`, `osm_type` or `extent`. A house result has no `name`.
- `state` holds the full name, `District of Columbia`, unlike the Nominatim server's `DC`.
- `limit` is honored. A search for `Springfield` with `limit=3` returned three US cities called Springfield.

Without an admin gazetteer, `/reverse` returns an empty feature collection with status 200:

```json
{
	"type": "FeatureCollection",
	"features": [],
	"engine": {
		"name": "mailwoman",
		"version": "11.0.0",
		"license": "AGPL-3.0-only",
		"license_url": "https://mailwoman.post/license",
		"notice": "mailwoman is licensed AGPL-3.0-only: modified or network-served copies must offer their source. A commercial license waives that obligation."
	}
}
```

## libpostal clients

The libpostal server parses and expands text without geographic data:

```bash
npx libpostal serve --port 7805 --host 127.0.0.1
```

It serves `GET` and `POST` on `/parse` and `/expand`. A parse:

```bash
curl -X POST http://127.0.0.1:7805/parse -H "content-type: application/json" -d '{"query":"781 Franklin Ave Crown Heights Brooklyn NYC NY 11216 USA"}'
```

```json
[
	{ "label": "house_number", "value": "781" },
	{ "label": "road", "value": "Franklin Ave" },
	{ "label": "city", "value": "Crown Heights Brooklyn NYC" },
	{ "label": "state", "value": "NY" },
	{ "label": "postcode", "value": "11216" },
	{ "label": "country", "value": "USA" }
]
```

The response is the ordered `label` and `value` array that libpostal REST services return. Values keep the input's casing. The three place names before the state came back as one `city` value, `Crown Heights Brooklyn NYC`. Check whether your client expects a neighborhood or district as a separate label.

An expansion:

```bash
curl -X POST http://127.0.0.1:7805/expand -H "content-type: application/json" -d '{"address":"781 Franklin Ave Brooklyn NY"}'
```

```json
{ "expansions": ["781 Franklin Ave Brooklyn NY", "781 Franklin Avenue Brooklyn NY"] }
```

## Check your client before switching

1. Send the requests your client makes in production to both the current service and the Mailwoman server.
2. List the response fields your client reads, and confirm each one is present in the Mailwoman response.
3. Handle the empty results described above: `null` from Nominatim `/reverse`, an empty feature collection from Photon `/reverse`, and status 501 from Nominatim `/lookup`.

Each server also serves `GET /openapi.json`, its machine-readable route description. The [HTTP reference](../reference/http.mdx) lists every compatibility route and its declared status codes.
