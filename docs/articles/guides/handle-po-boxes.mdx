# Route PO box records for mailing review

Use this guide when a <Country code="US" /> mailing-address intake needs to separate PO box records from records intended for a building-coordinate workflow. The example records a complete PO box parse as a mailing-address candidate for review and requests more input when the box has no locality, region, or postcode. These are application choices. Whether the box exists and accepts mail is a question for the postal service.

## Prerequisites

- Node.js 24 LTS or later.
- An ECMAScript module project, with `"type": "module"` in its `package.json`.

Install the published parser packages:

```sh
npm install --save-exact mailwoman@11.0.0 @mailwoman/neural@11.0.0 @mailwoman/neural-weights-en-us@11.0.0
```

The example uses the English model and reads no geographic database. Save the following complete script as `route-po-box.ts`.

## Parse and apply a mailing intake rule

```ts
import { createRuntimePipeline } from "mailwoman"
import { NeuralAddressClassifier } from "@mailwoman/neural"

const classifier = await NeuralAddressClassifier.loadFromWeights({ locale: "en-US" })
const parse = createRuntimePipeline({ classifier })

type TreeNode = Awaited<ReturnType<typeof parse>>["tree"]["roots"][number]
interface FlatNode {
	tag: string
	value: string
	start: number
	end: number
}

for (const input of ["PO Box 1234, Springfield, IL 62701", "PO Box 1234"]) {
	const result = await parse(input)
	const nodes: FlatNode[] = []
	function visit(node: TreeNode): void {
		nodes.push({ tag: node.tag, value: node.value, start: node.start, end: node.end })
		for (const child of node.children) visit(child)
	}
	for (const root of result.tree.roots) visit(root)

	const required = ["po_box", "locality", "region", "postcode"]
	const missing = required.filter((tag) => !nodes.some((node) => node.tag === tag))
	const mailingCandidate = result.kind.kind === "po_box" && result.faults.length === 0 && missing.length === 0
	console.log(
		JSON.stringify({
			input,
			kind: result.kind.kind,
			tree: nodes,
			decision: {
				route: mailingCandidate ? "mailing-address-review" : "request-more-input",
				missing,
				deliveryStatus: "unknown",
				buildingCoordinate: "unknown",
			},
		})
	)
}
```

The code flattens the returned tree for display and keeps each component's tag, value, and offsets. It requires both the `po_box` query kind and a `po_box` node. It also checks for a locality, region, postcode, and an empty `faults` array before placing a record in this application's mailing-review queue. A missing field sends the record to a request for more input. The application supplies the <Country code="US" /> mailing-intake context, separately from the parser locale.

Run `node route-po-box.ts`. The published 11.0.0 packages returned this complete output:

```json
{"input":"PO Box 1234, Springfield, IL 62701","kind":"po_box","tree":[{"tag":"region","value":"IL","start":26,"end":28},{"tag":"locality","value":"Springfield","start":13,"end":24},{"tag":"po_box","value":"PO Box 1234","start":0,"end":11},{"tag":"postcode","value":"62701","start":29,"end":34}],"decision":{"route":"mailing-address-review","missing":[],"deliveryStatus":"unknown","buildingCoordinate":"unknown"}}
{"input":"PO Box 1234","kind":"po_box","tree":[{"tag":"po_box","value":"PO Box 1234","start":0,"end":11}],"decision":{"route":"request-more-input","missing":["locality","region","postcode"],"deliveryStatus":"unknown","buildingCoordinate":"unknown"}}
```

For `PO Box 1234, Springfield, IL 62701`, the parser returned kind `po_box` and a `po_box` component containing `PO Box 1234`. The first record has the four components this intake requires, so the application routes it to mailing-address review. For `PO Box 1234`, the parse has the box component and lacks the three place fields, so the application requests more input. In both cases, delivery status and the location of a building remain unknown.

The script makes no geocode call. A coordinate returned for a city or post office needs its own source and precision evidence before any location use, and a PO box parse or a coarse place coordinate isn't a building destination. When you need a coordinate, first install and verify a [geographic data bundle](../reference/data-and-locales.mdx), then inspect the returned `resolution_tier`, `epistemic_status`, and coordinate provenance in the [result schema](../reference/schema.mdx). The [confidence and limits explanation](../explanation/confidence-and-limits.mdx) explains why a parser score answers neither the coordinate question nor the deliverability question.
