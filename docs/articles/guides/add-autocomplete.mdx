# Add place-name autocomplete

Use the published finite-state transducer (FST) to suggest **place names** as someone types. The FST in `@mailwoman/neural-weights-en-us@11.3.0` runs without a geographic database. Each suggestion is a place name with its Who's On First ID. Coordinates, street addresses, and delivery evidence come from other sources. This guide starts a local JSON endpoint and checks it with a fixed sequence of typing events.

## Prerequisites

<CommonPrerequisites />

Install the two packages the example uses:

```sh npm2yarn
npm install @mailwoman/resolver-wof-sqlite @mailwoman/neural-weights-en-us
```

Check that `node_modules/@mailwoman/neural-weights-en-us/fst-en-us.bin` exists in this project before starting the server. The path is relative to the project directory. The [data and locales reference](../reference/data-and-locales.mdx) distinguishes this place-name index from the geographic databases needed to resolve coordinates.

Port 3000 on your computer must be free for the local endpoint.

## 1. Start a suggestion endpoint

Save this code as `autocomplete-server.ts`. It loads the FST once and serves `GET /suggest?q=...` on your computer. Keep this process running while you check the endpoint in the next step.

```ts
import { createServer } from "node:http"
import { readFile } from "node:fs/promises"
import { autocomplete, deserializeFST } from "@mailwoman/resolver-wof-sqlite/fst"

interface Suggestion {
	name: string
	placetype: string
	wofID: number
}

const fst = deserializeFST(await readFile("node_modules/@mailwoman/neural-weights-en-us/fst-en-us.bin"))

const server = createServer((request, response) => {
	const url = new URL(request.url ?? "/", "http://localhost")

	if (url.pathname !== "/suggest") {
		response.writeHead(404).end()

		return
	}

	const query = url.searchParams.get("q")?.trim() ?? ""

	const entries: Suggestion[] =
		query.length < 3
			? []
			: autocomplete(fst, query, { maxSuggestions: 2, dedupeByName: true }).suggestions.map(
					({ name, placetype, wofID }) => ({ name, placetype, wofID })
				)

	response.writeHead(200, { "content-type": "application/json" }).end(JSON.stringify({ entries }))
})

server.listen(3000, "127.0.0.1", () => {
	console.log("Serving suggestions at http://127.0.0.1:3000/suggest")
})
```

Run `node autocomplete-server.ts` in the first terminal. The server prints:

```text
Serving suggestions at http://127.0.0.1:3000/suggest
```

## 2. Check typed inputs

Save this file as `autocomplete-check.ts` in the same project. It sends seven input events to the running endpoint. The client skips inputs shorter than three trimmed characters and suppresses an event when trimming leaves the same query as the previous request. The application chooses these rules.

```ts
interface Suggestion {
	name: string
	placetype: string
	wofID: number
}

let requests = 0
let lastQuery = ""

for (const input of ["s", "sa", "san", "san ", "san f", "san fr", "san franc"]) {
	const query = input.trim()

	if (query.length < 3) {
		console.log(`${JSON.stringify(input)}: skipped (short)`)

		continue
	}

	if (query === lastQuery) {
		console.log(`${JSON.stringify(input)}: skipped (unchanged)`)

		continue
	}

	lastQuery = query
	const response = await fetch(`http://127.0.0.1:3000/suggest?q=${encodeURIComponent(query)}`)

	requests++

	if (!response.ok) throw new Error(`HTTP ${response.status}`)
	const data = (await response.json()) as { entries: Suggestion[] }

	console.log(
		`${JSON.stringify(input)}: ${data.entries.map(({ name, placetype }) => `${name} (${placetype})`).join("; ")}`
	)
}

console.log(`HTTP requests: ${requests} of 7 input events`)
```

Run `node autocomplete-check.ts` in a second terminal while the server is running. The published 11.3.0 packages returned this complete client output:

```text
"s": skipped (short)
"sa": skipped (short)
"san": San Antonio (locality); San Diego (locality)
"san ": skipped (unchanged)
"san f": San Francisco (locality); San Fernando (locality)
"san fr": San Francisco (locality); San Francisco Township (localadmin)
"san franc": San Francisco (locality); San Francisco Township (localadmin)
HTTP requests: 4 of 7 input events
```

Four of the seven input events made HTTP requests: `san`, `san f`, `san fr`, and `san franc`. The first two events were below this example's three-character rule, and `san ` trimmed to the already-requested `san`. The server also checks short queries, so a direct request gets the same length rule as the client. `dedupeByName: true` keeps one entry per displayed name. It changes the second result for `san franc` from the CLI's default. The CLI example on the [capabilities page](/product/capabilities#what-the-autocomplete-check-established) leaves deduplication off.

The endpoint remains available after the client check. Stop it with Ctrl+C when you're done. In an application, send the search field's current value to `/suggest` using the same trim, length, and unchanged-query checks. Serve the endpoint from the application's origin when a browser page calls it. Render the returned `entries` as selectable place-name suggestions and keep each `wofID` as its place identifier. The example measures the request count for one fixed typing sequence. Measure response latency on your host and with your input mix before choosing a debounce delay.

The FST returns ranked gazetteer names and a `wofID` for each suggestion. See [geocoding](/docs/explanation/geocoding) for the separate lookup that supplies a coordinate, and [confidence and limits](/docs/explanation/confidence-and-limits) for evidence boundaries.
