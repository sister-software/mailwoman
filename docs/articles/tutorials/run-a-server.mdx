# Run the Mailwoman HTTP server

In this tutorial you start the native Mailwoman HTTP server on your machine and send it four requests: a health check, a parse, a geocode, and a request with a missing field. You then stop the server. Each step shows the complete response the server returned.

## Before you start

Use Node.js 24.22.1 or a later 24.x release. In an empty directory, install the published 11.0.0 packages:

```bash
npm install mailwoman@11.0.0 @mailwoman/neural@11.0.0 @mailwoman/neural-weights-en-us@11.0.0
```

The server refuses to start without geographic data. It exits with status 1 before listening when it finds neither a candidate database nor Who's On First databases. Download the global place candidates and the address points for Washington, DC:

```bash
export MAILWOMAN_DATA_ROOT="$HOME/mailwoman-data"
mkdir -p "$MAILWOMAN_DATA_ROOT"
npx mailwoman data pull candidate
npx mailwoman data pull us --only us-dc
```

The two pulls download about 3 GB: `candidate` 2.9 GB and DC 127.5 MB. If you completed [Geocode a file of addresses](./geocode-a-file.mdx), you already have both. The responses below were captured on Node.js 24.22.1 with local builds of these bundles that are newer than the 11.0.0 registry entries, so a coordinate or source release in your responses can differ.

## 1. Start the server

Start the server on port 7801 with one worker process, bound to your own machine only:

```bash
npx mailwoman serve --port 7801 --host 127.0.0.1 --cpus 1
```

The server reads its data from `$MAILWOMAN_DATA_ROOT`. It prints the database it opened, then the process IDs of its manager and worker once the worker is listening:

```text
[resolver] candidate-table backend (demo-parity, population-first): /home/you/mailwoman-data/db/wof/candidate.db
mailwoman is licensed AGPL-3.0-only: modified or network-served copies must offer their source.
A commercial license waives that obligation: https://mailwoman.post/license

Manager process: 3934763
Workers:
ℹ Listening (3934800) "HTTP server ready"
```

Your process IDs will differ. Leave this terminal running and open a second terminal for the next steps. Without `--cpus`, the server starts one worker per CPU core.

This page shows the data directory as `/home/you/mailwoman-data`, so the body is longer than the captured `content-length`. `status: "ok"` means the server answered. `model` identifies the loaded en-US model, version 10.8.0. `data` lists the data root and the place databases the server found there. On the host used for this page, the health route answered 13 seconds after the start command. The manager and worker processes then held 133,192 kB and 474,140 kB of resident memory after one geocode, about 607 MB in total. Those are single measurements from one Linux host. A server with more workers uses more memory.

`components` lists the tagged parts in input order. `tree` nests them from region down to house number, and each node's `start` and `end` give its character offsets in the input. A parse reads only the text. It doesn't look up any place, so it answers for a Vermont address even though this server has no Vermont address points.

## 5. Read an error response

Send a geocode request without an `address`:

```bash
curl -i -X POST http://127.0.0.1:7801/v1/geocode -H "content-type: application/json" -d '{}'
```

```http
HTTP/1.1 400 Bad Request
access-control-allow-origin: *
content-type: application/json
link: <https://mailwoman.post/license>; rel="license"
server: mailwoman/11.0.0 (AGPL-3.0-only)
content-length: 45
Date: Wed, 11 Nov 2026 04:01:17 GMT
Connection: keep-alive
Keep-Alive: timeout=5

{"error":"address is required","detail":null}
```

A request error returns a 4xx status with an `error` message. Check the status code in your client before reading the body as a result.

## 6. Stop the server

Send a termination signal to the manager process that the server printed at startup:

```bash
kill 3934763
```

The server drains its worker and exits with status 0. Its terminal prints:

```text
[serve] worker 3934800 draining
```

## What you learned

- `mailwoman serve` needs geographic data in `$MAILWOMAN_DATA_ROOT` before it will start.
- `GET /health` reports that the server is up and which model and databases it loaded.
- `GET /v1/parse` reads text without looking up places. `POST /v1/geocode` returns a coordinate and its source.
- A request error returns a 4xx status with an `error` message.

The [HTTP reference](../reference/http.mdx) lists every native route and the Nominatim, Photon and libpostal compatibility routes. [Choose a deployment](/product/deployment) compares running this server with the library and browser options.
