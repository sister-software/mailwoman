### Unit of every offset (observed from the source)

Every span `query-shape` returns is a half-open range of UTF-16 code units, because each one comes from `String.prototype.slice` indices or from a `text.length` count.
The tokenizer steps by code point (`i += cp > 0xffff ? 2 : 1`) and still reports UTF-16 offsets.
`RegionAbbreviationHit.start` and `totalLength` use the same unit.

Every consumer below assumes that unit. The one place where it needs care is `neural/lib/char-encoder.ts`, whose `TextSpan` units are one code point wide and hold UTF-16 offsets.

### Where each consumer runs

Observed: every package whose directory ends in `-worker` is absent from the import list.
Inferred for the rest, from what each package does: `corpus` and the `tools/` scripts run only in Node, `react` only in a browser, and `kind-classifier`, `locale-hint`, `phrase-grouper`, `neural` and `core` run in both Node and the browser, because `packages/mailwoman/lib/browser-runtime/classify.ts` loads the first three and the pipeline through a dynamic `import()`.
The docs demo bundles the package (`docs/plugins/runtime-assets/workspace/aliases.ts:11`).
Unknown: whether any bundle that reaches a Worker holds `query-shape` through a transitive import.

## 4. Legacy behavior that looks accidental, apart from behavior consumers depend on

### Consumers depend on these (keep them under decision 3)

- Hit names and confidences: `us_zip4` 0.95, `ca_postcode` 0.95 (one token) and 0.9 (two tokens), `jp_postcode` 0.95, `uk_postcode` 0.9, `nl_postcode` 0.9, the five-digit trio `us_zip`, `fr_postcode`, `de_postcode` at 0.6, the `NNN NN` quartet `cz`, `sk`, `se`, `gr` at 0.6, `po_box` 0.85. The prior scales its bias by confidence, the pipeline fast path writes it into the tree and `locale-hint` compares it with `UNAMBIGUOUS_FORMAT_CONFIDENCE`.
- Hit order: one-token hits in pattern order for each token, then two-token hits, then the single `po_box` hit. `locale-hint` takes `unambiguous[0]`.
- The `us_zip`, `us_zip4` and `*_postcode` naming convention behind `isPostcodeFormat`, which `core` repeats.
- A five-digit token reports three hits at once, so `12345 Main Street` reports `us_zip` at 0.6.
- `characterClass` is `alpha` for empty and punctuation-only input (`""`, `"???"`). A `kind-classifier` test comment documents the `???` case.
- Ten script values, with `Zzzz` for any other script (decision 4).
- Segments split on `,`, `;`, newline and tab. `;` is reported as `comma`.
- `regionAbbreviations` holds the 2-letter uppercase alpha tokens in a comma-separated segment after the first. The neural prior reads `start` and `span.length`.

### Look accidental (observed with `computeQueryShape` on the quoted input at the commit above)

1. **Greek, and every script outside the ten, reports `alphanumeric`.** `Αθήνα` gives `characterClass: alphanumeric`, token class `mixed`, script `Zzzz`. `classifyToken` returns `mixed` for a token with no class it knows, and `foldInputClass` turns any `mixed` token into `alphanumeric`.
2. **`jp_postcode` matches any `ddd-dddd`.** The `〒` is optional in `/^〒?\d{3}-\d{4}$/`, so `123-4567` reports `jp_postcode` at 0.95, and `locale-hint` turns that into `ja-JP` at 0.95.
3. **Two-token postcodes join across punctuation.** `Box 1012, LG` reports `nl_postcode` over `1012, LG` because the tokenizer drops the comma and the pair test joins neighbors with one space.
4. **A zero-width space blocks a postcode and sets the script to `Zzzz`.** `"​12345"` gives one `digit` token with script `Zzzz` and no `us_zip` hit, since the token body includes the zero-width space.
5. **Fullwidth Latin letters are class `cjk` and script `Latn`.** `ＡＢＣ １２３` gives `characterClass: cjk` and scripts `Latn: 1`. The class ranges include U+FF00 to U+FFEF whole. The script ranges split them.
6. **Only the first PO box is reported.** `PO Box 5, BP 7` gives one `po_box` hit.
7. **Two tie-breaks disagree.** For a token with equal Han and Latin counts, `classifyTokenScript("北a")` is `Hani` and `classifyTokenScript("a北")` is `Latn` (first seen wins), while `foldInputScripts` for both orders lists `Hani` then `Latn` (alphabetical on a tie). `scriptForRange` uses first seen too.
8. **A two-letter uppercase token is a region abbreviation in any non-first comma segment.** `Main St, NW, Washington` reports `NW`. The file comment limits it to `en-us`, and the code reads no locale.
9. **Single-token hits share the token's `span` object.** `knownFormats[0].span === tokenClasses[0].span` is `true` for `68161` (observed). The result is frozen at the top level only, so a write through one changes the other (inferred from `Object.freeze` in `compute.ts`).
10. **Parameters and values with no effect.** `segment(text, locale)` ignores `locale`. `SegmentSeparator` lists `whitespace` and `japanese-style`, and no code emits either. `whitespacePattern` has no reader.
11. **`RegionAbbreviationHit.span` is a string** where every other `span` is an object with `start`, `end` and `body`.

### Documentation drift (observed)

`packages/query-shape/README.md` describes `shape.script`, `shape.hasDigits`, `us_zip5`, `us_state_abbr` and whitespace values `structured`, `single_line` and `free_text`. None exists in `lib/types.ts`. `detectKnownFormats(segments)` takes `(text, tokens)` in the code.
