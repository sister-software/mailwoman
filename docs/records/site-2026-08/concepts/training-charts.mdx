# Training-run charts

The v0.6.x eval reports make claims such as "same noise pattern across runs" or "macro_f1 stable despite val_loss volatility." This article plots the data behind those claims and documents the charting tools.

## The v0.6.2 vs v0.6.2b comparison

Both runs trained on the v0.4.0 corpus with [synth-no-street](./corpus-poisoning-vulnerability.mdx) added. v0.6.2 used `synth-no-street: 1.0`, and v0.6.2b lowered it to `0.5`. All other settings were identical.

Each chart has a **Linear / Log** toggle. Use the log scale to examine small values and compress large spikes, and use the linear scale to read absolute magnitudes.

**val_loss over training steps:**

<TrainingChart src="/img/training-charts/v06x-val-loss.svg" alt="v0.6.2 vs v0.6.2b val_loss" />

Both runs spike into the 0.4–0.7 range periodically. I first read this as overconfidence drift on v0.6.2. The [v0.6.2 confidence probe](https://github.com/sister-software/mailwoman/blob/main/docs/records/evals/model-versions/2026-05-29-v0.6.2-100k-eval.mdx) ruled that out: the per-token confidence distributions of the two runs are essentially identical, with 81.2% vs 81.8% of wrong predictions at ≥0.9 confidence. The val_loss fluctuation comes from per-batch sample variance. It does not indicate a model-level change.

**val macro_f1 over training steps:**

<TrainingChart src="/img/training-charts/v06x-macro-f1.svg" alt="v0.6.2 vs v0.6.2b macro_f1" />

Despite the val_loss volatility, macro_f1 stays within the 0.39–0.42 band for both runs from step ~10K onward. This supports the reading that the val_loss spikes are batch-specific. macro_f1 aggregates true and false positives over the whole val set, and it stays flat. val_loss is sensitive to specific token-level probabilities, and it moves.

## How the charts are built

The charts come from plain scripts that need no charting library:

```bash
# 1. Pull a training-log CSV (committed when the training run ends):
modal volume get mailwoman-training output-v062/train_log.csv /tmp/v062.csv

# 2. Parse into structured JSON:
node scripts/parse-training-log.ts \
  --input /tmp/v062.csv --run-name v0.6.2 --out /tmp/v062.json

# 3. Generate the chart (linear):
node scripts/training-chart.ts \
  --input /tmp/v062.json --input /tmp/v062b.json \
  --metric val_loss --title "v0.6.2 vs v0.6.2b val_loss" \
  --output docs/records/evals/charts/v06x-val-loss.svg

# 4. Generate the log-scale variant (for the toggle):
node scripts/training-chart.ts \
  --input /tmp/v062.json --input /tmp/v062b.json \
  --metric val_loss --title "v0.6.2 vs v0.6.2b val_loss" --log \
  --output docs/records/evals/charts/v06x-val-loss-log.svg

# Or transform an existing linear SVG:
node scripts/log-scale-chart.ts \
  --input docs/records/evals/charts/v06x-val-loss.svg \
  --output docs/records/evals/charts/v06x-val-loss-log.svg
```

The parser detects whether its input is a CSV or a Modal log. The chart generator accepts multiple `--input` arguments to overlay runs and a `--log` flag for a log10 scale. It supports the `val_loss`, `macro_f1`, and `train_loss` metrics. The output is plain SVG without JavaScript, so it embeds in Docusaurus, GitHub, or any other page.

The `<TrainingChart>` component implements the **Linear / Log** toggle by switching between `chart.svg` and its `chart-log.svg` counterpart.

## When to read which chart

- **val_loss** is noisy in the short term, so read the trend rather than any single eval. Switch to **log scale** to examine the low-loss floor, and back to **linear** to compare spike magnitudes with the axis range.
- **macro_f1** is the steady-state quality signal. v0.6.x runs reach about 0.40–0.42 by step 20K and change little after that. A meaningful improvement shows as a sustained higher band. A single high reading does not indicate one.
- **train_loss** is for diagnostics only. It always drops monotonically, with small fluctuations, and a NaN or a step change appears here first. **Log scale** shows the asymptotic tail.

The v0.6.x training loop writes an eval row every 2K steps and a train_loss row every 50 steps. A 100K-step run produces ~50 eval points and ~2000 train-loss points.

## Limitations

- The charts are static SVG. The Linear/Log toggle is the only runtime control. To explore a single run interactively, open its CSV in a tool of your choice.
- Multi-run charts work only for runs whose CSVs have been committed to the Modal volume and pulled to the local machine.
- Modal app logs return only the last 100 lines by default.
