# Getting started

This guide covers installing Mailwoman, parsing an address from Node.js, and parsing the same address from the CLI. It takes about five minutes.

## Prerequisites

- **Node.js ≥24.18.0.** Mailwoman's source runs directly under `node` using type stripping, so consumers need no build step. Earlier Node versions cannot strip types the way the package expects.
- **A ~33 MB download for the English weights.** `@mailwoman/neural-weights-en-us` ships a 37.6 MB int8 ONNX model, the tokenizer, and a few small lookup files. npm compresses them to a ~33 MB download (~41 MB unpacked). The French weights (`@mailwoman/neural-weights-fr-fr`) are a separate package of similar size.

## Install

```bash
npm install mailwoman @mailwoman/neural @mailwoman/neural-weights-en-us
```

This installs the CLI, the neural runtime, and the English weights. Add
`@mailwoman/neural-weights-fr-fr` for French addresses.

## Your first parse (Node.js)

The recommended entry point is `createRuntimePipeline` from the `mailwoman` package. It builds the full stage pipeline (normalize → locale check → kind classify → phrase group → token classify) around the classifier and resolver you pass in:

```ts
import { createRuntimePipeline } from "mailwoman"
import { NeuralAddressClassifier } from "@mailwoman/neural"

const classifier = await NeuralAddressClassifier.loadFromWeights({ locale: "en-US" })
const pipeline = createRuntimePipeline({ classifier })

const result = await pipeline("350 5th Ave, New York, NY 10118")

function printNode(node, depth = 0) {
	console.log(`${"  ".repeat(depth)}${node.tag}: "${node.value}" (confidence: ${node.confidence.toFixed(2)})`)
	for (const child of node.children) printNode(child, depth + 1)
}

for (const root of result.tree.roots) printNode(root)
```

Output:

```
region: "NY" (confidence: 0.93)
  locality: "New York" (confidence: 0.89)
    street: "5th" (confidence: 0.95)
      house_number: "350" (confidence: 0.88)
      street_suffix: "Ave" (confidence: 0.95)
    postcode: "10118" (confidence: 0.92)
```

`result.tree.roots` is a tree nested by containment. Each component sits inside the component that contains it. A `region` contains its `locality`, which contains its `street` and `postcode`. Walk it with recursion rather than a single loop.

The confidence numbers are calibrated probabilities. With the bundled per-locale calibrator, "0.90" means the label is correct about 90% of the time. See [Confidence calibration](./concepts/confidence-calibration.mdx) for how to load it.

`result` also carries `result.kind` (the query-shape classification, e.g. `structured_address`), `result.path` (`"full"` or `"fast-path"`), and `result.timing` (per-stage wall-clock time in milliseconds). See [API reference](./api.mdx) for the full `PipelineResult` shape.

:::info[Direct classifier access]
If you don't need the staged pipeline stages (normalize, locale check, phrase grouping, resolution), call `NeuralAddressClassifier.parse()` directly. It runs only the neural stage and returns the same `AddressTree` shape. See [API reference](./api.mdx#neuraladdressclassifier) for the signature.
:::

## CLI

After the weights are installed, run the same parse from the command line:

```bash
mailwoman parse "350 5th Ave, New York, NY 10118"
```

Output:

```json
{
	"region": "NY",
	"locality": "New York",
	"street": "5th",
	"house_number": "350",
	"street_suffix": "Ave",
	"postcode": "10118"
}
```

This is the flattened projection (`--format json`, the default). It has one key per component tag and is easier to skim than the nested tree. `--format tuple` emits `[tag, value]` pairs, and `--format xml` emits the nested tree as XML. Add `--resolve --resolve-db <path-to-wof.sqlite>` to look up components in a Who's On First gazetteer distribution. See [API reference](./api.mdx#createwofresolverbackend) for what resolution adds and where to get a distribution.

## Caveats

- **The resolver behind `--resolve` works at the administrative and postcode level.** It returns place centroids (locality, region, postcode) rather than delivery-point coordinates. Rooftop and interpolated street-level resolution are available through the separate `mailwoman geocode` command. See [Status](./status.mdx) for what is covered.
- **Model quality varies by component and locale.** Some tags are strong, and others are still developing. [Status](./status.mdx) has the current per-tag numbers. Check it instead of relying on numbers quoted on other pages, which can go out of date.
- **Non-Latin scripts still perform worse.** The tokenizer falls back to byte-level encoding for scripts without dedicated subwords (Cyrillic, CJK, Arabic). Confidence drops and span boundaries become less reliable. Several languages written in Latin script with diacritics (French, Czech, Polish, Slovak, Slovenian, the Nordic languages) have dedicated tokenizer coverage. See [Releases & capabilities](./releases.mdx) for which release added each one, and [which languages Mailwoman handles well](./concepts/language-support.mdx) for the full picture.
