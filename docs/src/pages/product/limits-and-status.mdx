# Limits and release status

This page records the evidence checked on 9 November 2026 for published `mailwoman@11.0.0`. A package declaration, a downloadable data bundle, an installed database, and a coordinate-graded evaluation answer different availability questions. Check your own installation before relying on a coordinate result.

| Question                             | Checked answer for 11.0.0                                                                                                                                 | Evidence boundary                                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| What does npm publish?               | The `mailwoman` CLI and parser library, with separately installed model packages. The en-US weights package is 11.0.0 and identifies its model as 10.8.0. | Published package metadata and model card.                                                                                                         |
| What data can be downloaded?         | The package registry declares `candidate`, `poi`, `fr`, and `us` bundles.                                                                                 | Registry estimates describe the declared bundle entries. This page checked no downloaded files.                                                    |
| What can a user build locally?       | The published CLI exposes the `osm-address-points` recipe for CA, DE, FR, GB, ID, NL, NZ, PK, PL, and VN.                                                 | A recipe and eligible country do not mean its source data has been acquired or its output installed.                                               |
| What was installed for this check?   | The published CLI reported missing artifacts for all four bundles in the verification host's default data root.                                           | A reader must check their own installation separately.                                                                                             |
| What has coordinate-graded evidence? | The maintained scope declaration cites dated coordinate panels for its graded tiers and separate character-path evidence.                                 | The evaluation ledger does not establish a coordinate panel for the exact 11.0.0 release and model 10.8.0. That release-matched status is unknown. |

The published `mailwoman@11.0.0` package declares Node.js `^24.22.1 || >=26.12.1`. The published `@mailwoman/neural-weights-en-us@11.0.0` model card identifies model version `10.8.0`. A [first parse](/docs/start) was executed with those packages on Node.js 24.22.1. The parser runs without a gazetteer. The geocoder and native server need suitable local geographic data.

## Downloadable data in the published registry

The table gives the package registry's `approxBytes` estimates. This verification environment did not download the files to measure their sizes. The `us` bundle consists of per-state files. The registry declares 103 artifacts for that bundle.

| Bundle      | Registry description                                   | Declared artifacts | Registry `approxBytes` total |
| ----------- | ------------------------------------------------------ | -----------------: | ---------------------------: |
| `candidate` | Global administrative candidates and postcode coverage |                  1 |                2,880,921,600 |
| `poi`       | Point-of-interest layer for US, CA, MX, and FR         |                  1 |                3,889,184,768 |
| `fr`        | French BAN address points                              |                  1 |                6,952,509,440 |
| `us`        | US address-point and interpolation files               |                103 |               41,463,517,184 |

The published `mailwoman data --list` command prints these four names and rounded size estimates. The totals above sum each bundle's declared artifact `approxBytes` values. A bundle's listed geographic reach does not mean that every address in that area has a matching point. [Data and licensing](/product/data-and-licensing) describes recorded sources and unresolved rights questions for each bundle.

The [data and locales reference](/docs/reference/data-and-locales) lists each bundle's role, dependency, and locale mechanism.

The published `mailwoman data build --help` command names `osm-address-points` as its build recipe. Its published recipe lists CA, DE, FR, GB, ID, NL, NZ, PK, PL, and VN as eligible countries. A build requires its source inputs and a completed run. The repository also contains other build tooling. Only `osm-address-points` appeared in the published CLI help checked for this page.

To inspect your own installation, run `mailwoman data status` and `mailwoman doctor` in the environment that will serve requests. In the verification host's default data root, `mailwoman data status` exited 1 and reported each of the four bundles as missing. No geocode response was verified for this page.

## Locale claims and evaluation

The maintained [scope declaration](https://github.com/sister-software/mailwoman/blob/main/docs/engineering/SCOPE.mdx) and [scope register](https://github.com/sister-software/mailwoman/blob/main/scope.config.json) assign these locale tiers. The tiers describe project claims and delivery mechanisms. They do not state that a data bundle is installed on a reader's machine.

| Scope classification      | Countries in the maintained register                   | What the classification records                                                                       |
| ------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Tier 1                    | US, FR                                                 | First-class claim with project evaluation records.                                                    |
| Tier 2                    | AT, AU, BE, CH, CZ, DE, DK, ES, FI, HR, IT, NL, PL, PT | Trained locales with dated coordinate panels.                                                         |
| Tier 3                    | NO, SE                                                 | Trained exposure with thinner dated coordinate evidence.                                              |
| Tier 4                    | CZ, PL, SI, SK                                         | Shipped diacritic-tokenizer mechanism. CZ and PL also belong to tier 2.                               |
| Tier 5                    | JP, KR, TW                                             | Published character-path mechanism with country-specific evidence described in the scope declaration. |
| Untiered shipping locales | CN, GB, IN, NZ                                         | The scope register records why these shipping locales have no tier claim.                             |

The scope declaration cites coordinate evaluations for its graded tiers and describes separate JP, KR, and TW evidence. Those records come from earlier artifacts and dated panels. The [evaluation ledger](https://github.com/sister-software/mailwoman/blob/main/evals/scores-by-version.json) has a model 10.8.0 entry with label and arena metric groups. A coordinate-graded result for the exact 11.0.0 published package and current data bundles is unknown from that ledger. The `candidate` bundle's declared 244-country coverage describes place data. The scope declaration supplies the separate evidence for evaluated accuracy.

For the current API fields and their evidence scopes, read the [result schema](/docs/reference/schema). [Start with one parse](/docs/start) before installing geographic data, or return to the [product overview](/product) for the parser and geocoder split.

The [benchmark evidence index](/evidence/benchmarks) separates historical panels from evidence for the published 11.0.0 release.
