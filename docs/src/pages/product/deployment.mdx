# Choose a deployment shape

Choose where the caller needs the result and whether the result needs geographic data. This comparison applies to published Mailwoman 11.0.0. A parse labels address text. A geographic lookup needs a suitable local database. The library and browser parse paths below have executed examples. A data-backed HTTP deployment has not been run in this verification installation.

| Shape               | Choose it when                                                                      | Files and data to provide                                                                                                      | Checked status and next step                                                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node.js library     | An existing Node.js application needs parse results in its own process.             | Install the `mailwoman` and model packages. Add a resolver and local geographic data only for a geographic lookup.             | The published 11.0.0 [first parse](/docs/start) ran on Node.js 24.22.1. Use the [library reference](/docs/reference/library) for its interfaces.                                                                                      |
| Browser             | A page needs parse components in the tab.                                           | Serve the model, tokenizer, lexicons, postcode data, pair index, and ONNX WebAssembly runtime from the application's origin.   | The published 11.0.0 [browser parse](/docs/guides/parse-in-browser) ran in Chromium 156. This checked path returns components without a geographic lookup.                                                                            |
| Native HTTP service | Several clients need a shared HTTP interface.                                       | Install the Node.js packages and a valid candidate or Who's On First database before launching `mailwoman serve`.              | The published command exited before listening without that database. Read the [HTTP reference](/docs/reference/http) and [data prerequisites](/docs/reference/data-and-locales). A complete service response remains unverified here. |
| Container           | A team wants to package the native service and its local data for a container host. | Supply an image built for the chosen platform, the required Node.js runtime, and a readable database path.                     | No published 11.0.0 image or data-backed container run was checked for this page. Treat container readiness and capacity as unknown until that image and database are tested.                                                         |
| Serverless          | An operator must fit a library call or HTTP handler within a platform's limits.     | Check that platform's Node.js version, package limit, filesystem behavior, and database access against the selected operation. | No published 11.0.0 serverless handler or data-backed run was checked here. Memory, cold start, and host compatibility are unknown.                                                                                                   |

## Size the files you control

The [packages and runtime reference](/docs/reference/packages-and-runtime) measured apparent directory sizes with `du -sb` in one Linux x86_64, Node.js 24.22.1, npm 11.19.1 installation of published 11.0.0 packages. `node_modules/mailwoman` occupied 17,969,301 bytes, `node_modules/@mailwoman/neural` occupied 1,649,870 bytes, and `node_modules/@mailwoman/neural-weights-en-us` occupied 65,018,687 bytes. These measurements cover three individual package directories. Other installed dependencies, geographic databases, and runtime memory were not measured.

The [browser guide](/docs/guides/parse-in-browser) copied ten model and supporting assets totaling 42,850,059 bytes, plus an ONNX Runtime `.mjs` and `.wasm` pair totaling 14,873,590 bytes. The sum is 57,723,649 copied asset bytes for that example. Headless Chromium 156.0.8078.4 fetched 44,150,884 encoded bytes across 16 completed requests from a local Vite production preview with its cache disabled. Those requests include the page and generated scripts. A different browser, cache state, or server compression policy can change the transfer. Browser memory was not measured reliably.

The published [bundle registry estimates](/product/limits-and-status#downloadable-data-in-the-published-registry) list 2,880,921,600 `approxBytes` for the candidate bundle. This registry value estimates downloadable bytes. Installed size and service memory remain unknown. This verification installation has no valid candidate or Who's On First database. The native server's storage after installation, request latency, and capacity are also unknown here.

## Check the deployment before serving requests

The published `mailwoman@11.0.0` manifest requires Node.js `^24.22.1 || >=26.12.1`. Use that requirement for a Node.js application, native service, or Node.js based container or serverless host. The browser runs the generated JavaScript and WebAssembly separately from the build machine's Node.js process.

For an HTTP deployment, first identify the database path in the target environment. The [data reference](/docs/reference/data-and-locales#check-an-installation) gives the published `data status` and `doctor --verbose` checks. The published `mailwoman serve` command exited 1 before listening in an empty data root with `createServeEngine: no WOF DBs found — set MAILWOMAN_WOF_DB or MAILWOMAN_CANDIDATE_DB`. The [HTTP schema](/docs/reference/http) describes declared routes and responses. A live health check, parse response, geocode response, and resource measurement still require a valid database and a tested deployment.

Start with the [first library parse](/docs/start) if a Node.js application can own the call. Use the [browser parse guide](/docs/guides/parse-in-browser) if the page needs components without a service. For a shared HTTP deployment, inspect the [data requirements](/docs/reference/data-and-locales) and the [published route schemas](/docs/reference/http) before sizing a host.
