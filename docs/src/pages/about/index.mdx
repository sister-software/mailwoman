The parser turns address text into labeled components. A separate geocoder uses geographic data to select a place or coordinate. [The product overview](/product) explains the split, and [the first-parse tutorial](/docs/start) shows a published 11.0.0 result.

Sister Software maintains the project and publishes its source at [sister-software/mailwoman](https://github.com/sister-software/mailwoman). The project aims to make address processing inspectable and usable without sending each query to a service operated by the maintainers. The repository, published packages, and local-data setup give users control over the software and geographic data they run. [Data and licensing](/product/data-and-licensing) records the source terms and open rights questions for published bundles.

## Contact and support

For a project question, licensing discussion, or commercial inquiry, email [teffen@sister.software](mailto:teffen@sister.software). The repository's [issue-template configuration](https://github.com/sister-software/mailwoman/blob/main/.github/ISSUE_TEMPLATE/config.yml) directs general questions and design discussion to that address. The [license page](/license) uses the same contact for licensing questions.

For a reproducible bug or feature request that's safe to discuss publicly, use the [GitHub issue forms](https://github.com/sister-software/mailwoman/issues/new/choose). A bug report should include the exact input, expected and observed results, the first visible mismatch, and the package and data versions. [Report a parsing or geocoding problem](/docs/guides/report-a-problem) shows how to prepare that evidence. Keep private customer addresses and credentials out of public issues.

## Report a vulnerability privately

Email [teffen@sister.software](mailto:teffen@sister.software) for a security vulnerability. The [security policy](https://github.com/sister-software/mailwoman/blob/main/SECURITY.md) asks for the impact, steps or proof of concept, and the affected version or commit. Send exploit details by email so they're available to the maintainer without publishing them in a GitHub issue.
