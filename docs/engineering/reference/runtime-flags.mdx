# Runtime-flag register

**The policy ([SCOPE](../SCOPE.mdx), invariant 5):** a runtime flag is a measurement instrument,
not a home. Every default-off feature exists to be measured; at each consolidation it either
earns default-on with an eval result, stays explicitly experimental with a named blocker, or is
retired. This register is the accounting — a flag with no row here is a smell, and a new flag
lands with its row in the same PR.

Enumerated from the option surfaces 2026-07-02 (`CreateRuntimePipelineOpts`, `PipelineOpts`,
`ClassifierOpts`, `ResolveOpts`, `ParseOpts`, `NeuralAddressClassifierConfig`, `CreateScorerOpts`,
`GeocodeDeps`, the policy registry, the drop-in CLIs, and the demo cascade). Tuning sub-knobs
(bias scales, radii, lookup caps) are listed with their owner flag, not separately.

## Deprecated

Empty, and kept empty on purpose. A flag that preserves a known-wrong behavior is a defect with a config
key, and "delete at the next major" is how one earns tenure — the three rows that used to sit here had
all decayed differently by the time anyone looked:

- `forceJointReconcile` was **already gone from source**; the row promised to delete a flag that did not exist.
- `cityStateFallback` was documented as "alias still honored" and was read by **nothing**. A consumer passing `cityStateFallback: false` got hierarchy completion anyway — a silent no-op that reads as an opt-out — and the test asserting the alias worked never passed the alias.
- `trailingLocality` was a live, opt-in, measured-net-negative prior that **no production path opted into**; the census verified it inert on 558/558 board rows and said so: "the honest end state is deletion, not a permanent allowlist row."

All three are deleted. Retire a mechanism by removing it, and remove its prose in the same commit — a
stale docstring outlives the code it described and is what people quote.
