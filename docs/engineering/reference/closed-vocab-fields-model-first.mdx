# Closed-vocab fields: model-first, with a soft gazetteer anchor

This page describes how Mailwoman handles the closed-vocabulary address fields `country`,
`po_box` and `cedex`. We resolve them **inside the model**, with a gazetteer fed in as a
soft feature, instead of overriding the model with a deterministic post-parse lookup.

:::info[Supersedes the night-9 overlay conclusion]
A first pass (2026-06-09 night shift) concluded that a deterministic post-parse overlay
(`ClosedVocabTagger`, issue #464) should tag these fields. That conclusion was
**reversed** after review. It rested on an unfair comparison, and it contradicts the
project's model-first approach. This page is the corrected design record. The design was
reviewed in a two-turn DeepSeek consultation, and the rationale follows below.
:::

:::tip[Generalized to street registries]
[Registry-backed structured prediction](./registry-backed-structured-prediction.mdx)
applies the same principle to street names, where national registers are complete enough
to make substitution tempting. That page defines the source capability tiers and the
positive-evidence-only rule.
:::

## Decision

1. **The model is the authority for every field, including closed-vocab fields.** We do
   not override its output with a lookup table.
2. **The gazetteer enters as a soft feature and never substitutes for the model's
   output.** This is the same principle as the [postcode anchor](./QUERY_SHAPE.mdx).
   `codex`'s matchers (`matchCountry`, `matchPOBox`, the cedex pattern) change role from
   _override_ to _feature-source_.
3. **Training covers starved closed-vocab fields** with the same negative-space recipe
   that fixed `unit`. See [negative space](../../records/site-2026-08/concepts/negative-space-coverage.mdx).

## Why not a deterministic overlay — the reasoning

**The over-firing came from the training data.** The night-9
`country` recipe produced almost entirely _trailing-country_ rows. The model learned the
shortcut "trailing token ⇒ country" and tagged cities and regions as countries (49 F1, 23%
precision). A skewed training distribution caused this result, and it does not show a
limit of the transformer+CRF architecture. Context-sensitive token classifiers (BERT+CRF,
LUKE, BLINK) routinely resolve gazetteer homographs from local context. Tagging "Atlanta,
Georgia" as a region and "Tbilisi, Georgia" as a country is the _canonical_ task of a
context-sensitive tagger.

**The "deterministic = 100%" result was misleading.** It was measured on a curated eval
with **zero homographs**, against a badly trained model. A flat lookup _cannot_ handle the
homograph case without a hand-coded guard, and such guards grow into the exception lists
the project rejects
([provenance-first](../../records/site-2026-08/concepts/corpus-poisoning-vulnerability.mdx)).
The overlay achieves perfect precision only on the easy cases.

**It contradicts a principle we already adopted.** The postcode-anchor work established
that lexicon signals enter as a _soft channel and never substitute for the model_. A
post-parse override is exactly the substitution we ruled out.

**A hard guarantee belongs in the resolver.** A wrong `country` puts the result on the
wrong _continent_ downstream, so a hard guarantee is a reasonable goal. The
**resolver should enforce it using calibrated confidence** (we ship isotonic `conf=`). If
the model has low confidence _and_ the gazetteer has an unambiguous match, the resolver may
prefer the lookup as a candidate. That is a re-rank at the resolution layer instead of a
substitution in the parser, and it provides the same safety.

## Revised taxonomy (three tiers, all model-first)

The night-9 split of "open-vocab → train / closed-vocab → deterministic" was too coarse. The
useful partition is by _what the field needs to learn_:

| Tier                                                 | Fields                                   | Treatment                                                                                                                                               |
| ---------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Open-vocab, starved**                              | `unit`, `street_prefix`, `street_suffix` | coverage recipe + retrain (proven: `unit` 0→92%, sharpened neighbors)                                                                                   |
| **Closed-vocab, without homographs, starved**        | `po_box`, `cedex`                        | also a coverage recipe — they were starved rather than unlearnable. "PO Box"/"CEDEX" carry no ambiguity, so no anchor is needed; train them like `unit` |
| **Closed-vocab, large set + homographs + long tail** | `country`                                | balanced coverage recipe **plus** a soft gazetteer anchor feature (long-tail recall floor + homograph flag). The only tier that needs the feature       |

None of the tiers uses a deterministic _override_.

## Architecture: a soft gazetteer anchor

For `country`, the matcher produces per-token features that feed into the transformer's
token representation, using the same implementation as the postcode anchor. The model
decides every tag. The features are:

- **Binary gazetteer-match flag:** "this token/sequence is a known country surface form."
  Its main purpose is **long-tail recall**. With ~250 countries at realistic prevalence, a
  small country appears only a handful of times in training. The flag gives the model a
  prior that it cannot learn from the subword embeddings of 3 examples. The flag cannot
  help with OOV or misspelled forms, and the model correctly handles those on its own.
- **Known-homograph flag:** "this surface form is _also_ a US state or region name." This
  is the most valuable bit, because it tells the model to rely on context instead of a
  shortcut. It is produced statically by intersecting the country and region gazetteers.
  It is expected to _improve_ `region` precision.
- **Optional entity-type embedding:** a small learned vector that includes the signal type
  (is-country / country+region-homograph / cedex / po_box). It costs almost nothing and
  lets the model learn a distinct behavior for each signal.

The codex matcher is reused. It stops overriding the model and instead supplies features to it.

## Data + training recipe

The recipe keeps the model from learning the positional shortcut and gives it enough
examples to learn from context:

- **Position variety:** leading, middle, trailing, and **absent** country. If every row
  ends with a country, the CRF learns a transition prior that destroys recall on the
  common absent-country address.
- **Explicit homograph pairs** disambiguated _within the same address window_: Atlanta vs
  Tbilisi Georgia, Paris TX vs Paris FR, San José CR vs CA.
- **Hard negatives:** state and province codes that are also country codes (CA, GA, IN,
  MA…), and countries that are also person names (Jordan, Chad, Dominica).
- **Realistic prevalence with loss-level compensation.** Do not inflate country everywhere,
  because that recreates the over-firing. Target **~12–18%** of rows carrying a country.
  Compensate for the imbalance with a **class-weighted CRF loss (~3–5× on B/I-country)**
  and light **transition regularization** instead of raw oversampling. Validate on a
  held-out set at _production prevalence_ (~5%) so the transition prior stays
  representative.

## Eval-first — because the last measurement misled us

Before any retrain, build a **hard homograph eval that a shortcut cannot pass** (~500–1000
rows). Re-measure the current model on it to get the _true_ baseline. The 27% figure was a
separate US-order artifact, and the number under homograph stress is unknown. The eval
must contain:

- ≥50 **homograph pairs**: the same ambiguous token with opposite labels, distinguished
  only by real neighbor tokens and without any cue a regex could exploit.
- ≥30 **state-code-as-country** negatives (CA/GA/IN/MA… as state _and_ as country).
- ≥20 **person-name-as-country** negatives.
- ≥20 non-trailing positions and **≥30% absent-country** rows (to measure O-emission /
  hallucination).
- a handful of **long-tail countries** (Eswatini, Timor-Leste, São Tomé) for recall.

**Acceptance (per-tag no-regression):** `country` improves, and `region`/`locality` stay
flat. Run DeepSeek's A/B/C control: the current model, the soft feature on the old corpus,
and the soft feature on the balanced corpus. The control shows whether the _feature_ or the
_data_ improves `country`, so we can skip the feature if balanced data alone is enough.

## How the field handles this (prior art)

Existing systems follow one of two approaches:

- **Parse-time structured tagging** produces an authoritative field-tagged record
  (Mailwoman, Pelias, libpostal, deepparse). Over-firing occurs in this approach.
- **Index-time disambiguation** does not commit to a parse and lets retrieval decide
  (Airmail).

| System                     | Approach to `country` / closed-vocab                                                                                                      | Lexicon used as                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **libpostal**              | `country`/`po_box` are _learned_ labels, same footing as everything                                                                       | input feature + training-data generator (end-to-end; inherits the over-fire risk) |
| **deepparse**              | learned labels, configurable tag set                                                                                                      | — (no overlay)                                                                    |
| **Pelias Parser**          | dictionary classifiers + cartesian solver                                                                                                 | fully deterministic (no ML to inform)                                             |
| **Pelias Placeholder**     | deterministic WoF hierarchy resolution downstream of the parse                                                                            | a resolution layer rather than span re-tagging                                    |
| **Nominatim**              | `countrycodes` is a hard filter; special phrases                                                                                          | deterministic overlays on search                                                  |
| **Google libaddressinput** | per-ISO-country deterministic metadata                                                                                                    | validation/format engine without free-text parsing                                |
| **Airmail**                | parserless by default; small BERT to aid malformed queries; country baked into a flat content field at index time, S2 cells for hierarchy | OSM `key=value` as a separate deterministic _index-time_ tag channel              |

**Where we sit.** Existing systems fall into two groups. libpostal and deepparse learn every
label and carry the over-firing risk. Pelias, Nominatim and libaddressinput treat country
deterministically, but none of them is an ML parser. Our position is to _keep the model
authoritative for every field and feed it the gazetteer as a soft feature_. We call this
the **model-first synthesis**: the lexicon informs the model without overriding it. The
closest related design is Airmail, which gives closed categorical vocabulary a
deterministic _channel_ (its OSM tags) alongside the fuzzy path. Airmail applies that
channel at index time, however, and takes the _opposite_ approach to label granularity. It
merges labels and tolerates confusion, while we add labels and make them more precise.

Pelias's legacy `addressit` shows why the model must learn to handle homographs. It parsed
`CA` into a `region='CA'` subquery and _never_ produced a `country='Canada'` alternative
([pelias/api #1287](https://github.com/pelias/api/pull/1287)).
