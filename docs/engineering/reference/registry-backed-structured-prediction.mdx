# Registry-backed structured prediction

This page describes how Mailwoman may use address registries (BAN, BAG, TIGER, WOF, OSM)
and why they feed the model instead of deciding for it.

In one sentence:

> **Registries provide soft lexical priors and synthetic coverage. The model still resolves
> ambiguity.**

This page extends [closed-vocab fields: model-first](./closed-vocab-fields-model-first.mdx)
to streets. That page decided `country` / `po_box` / `cedex`: the gazetteer enters as a soft
feature and never substitutes for the model. This page decides street names. The temptation
to substitute is much stronger here, because a national register does contain every street.

## What this is not

This design sits between two architectures, and both have already failed in this project.
The page describes them because future conveniences will tend to move the design toward one
of them.

### Not a dictionary parser

Pelias matches phrases against curated dictionaries. It works very well on exact template
matches and fails badly on messy input, because its hypothesis space is **closed**: it
cannot propose a phrase that its dictionaries do not contain. The dictionaries themselves
show this. In `pelias/parser/resources/pelias/dictionaries`, each file records a synonym or
word fragment that broke something. Some entries are fixes for past failures and others are
reasonable design choices, and it is hard to tell which is which. That ambiguity is a cost
of the architecture itself, and better maintenance would not remove it.

A register used as a veto behaves like a dictionary parser with probabilities attached. It
fails on the same input for the same reason: it penalizes a street because the register has
not seen it.

### Not resolver-as-arbiter

Phase 4a tried to let the resolver choose between k-best readings. That approach fails for
a structural reason that tuning cannot fix: **the resolver needs a house number or a
locality to resolve, so it has no evidence for exactly the bare fragments that need it.**
`Rue Montmartre` alone gives the resolver nothing to resolve, so it cannot choose a reading
for the class that motivated this work. This result was measured. See the Phase 4a
verdict.

Both failures follow the same pattern. A component downstream of the model was asked for
certainty that the model lacked, and it returned confidence without the evidence to support
it.

## The two channels

A registry can influence the parse in exactly two ways. The model makes every other
decision.

### 1. Soft lexical prior

The prior is a positive-only bias, weighted by source tier and scope. Its constant is tuned
**per locale family** rather than once globally.

### 2. Synthetic coverage

Phenomenon recipes run at a capped ratio and are split source-disjoint by normalized street
surface. If the model has never seen a bare street, inference-time evidence cannot fix its
prior. The cause is the training distribution, so the fix belongs in training.

## The provider

All registry evidence goes through one abstraction, so that a tier cannot gain a capability
it was not granted without that change being visible:

```ts
interface StreetNameEvidenceProvider {
	lookup(surface: string, locale: LocaleHint, scope?: EvidenceScope): StreetNameEvidence
}

interface StreetNameEvidence {
	exists: boolean
	confidence: number
	source: string
	sourceTier: EvidenceTier // A | B | C | D
	scopeLevel: ScopeLevel // global | region | locality | postcode
	frequency: number
}
```

`sourceTier` is part of the return value, so a consumer does not have to derive it by
pattern-matching `source`. Confidence depends on tier and scope, so the tier must be
available where the bias is applied.

### Rules

1. **Use positive evidence only.**
2. **Confidence depends on source tier and scope.**
3. **Never apply a global veto.**
4. **Tune bias per locale family** rather than using one universal constant.
5. **Split eval/train by street surface** rather than by record row.

Rule 1 is the rule most likely to be broken. Negative evidence from an incomplete register
reproduces Pelias's dictionary failure in a soft form. It penalizes real streets that the
register lacks, everywhere, and the penalty is hard to see because it looks like a
probability instead of a missing dictionary entry. No tier supplies global negative
evidence, including the tiers that are complete in principle.

Rule 5 addresses a problem we have already encountered in a similar form. A row-disjoint
split lets the same street surface appear on both sides of the boundary. The eval then
measures memorization of `Rue de Rivoli` while appearing to measure generalization to
unseen streets.

## Capability tiers

| Tier  | Data                                                         | Allowed use                                  | Not allowed                                                         |
| ----- | ------------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------- |
| **A** | Authoritative street/address registers — FR BAN, NL BAG-like | Eval, augmentation, positive name-index bias | Negative evidence                                                   |
| **B** | Road/address-range data — US TIGER                           | Positive bias **only with scope**            | Unscoped/global evidence; negative evidence                         |
| **C** | Admin gazetteers — WOF                                       | Locality/region/country evidence             | **Street existence**; negative evidence                             |
| **D** | OSM-like broad data                                          | Experiments, coverage-gap analysis           | Product use without licensing/attribution review; negative evidence |

### Tier A — start here

BAN is the first test case because it is clean, national, and complete for street names.
It is the only tier where the absence of a street carries any information, and the only
source against which the augmentation can be graded with real data. Other locales follow
**by tier, afterward**, as a separate step.

### Tier B — scope is the whole rule

`Main St` without scope is weak evidence. It exists in nearly every US locality, so its
existence does not distinguish anything. `Main St` with `CA`, `Santa Clara`, or a ZIP is
useful.

This tier has a trap that must be stated explicitly, because the same problem ended Phase
4a: **scoping reintroduces the dependency on a locality.** If the scope has to come from a
resolve, Tier B has no evidence for exactly the bare fragments that need it. Tier B
evidence is usable only when the scope is present in the input.

### Tier C — the famous-street-as-place trap

WOF carries admin polygons. It also carries famous streets **as places**, and `rue`,
`boulevard`, and `place` are gazetteer entries themselves. Reading a WOF hit as evidence
that a street exists reverses its meaning. `Rue Montmartre` then looks like evidence for
`locality`, which is the error this work is trying to fix.

This was measured. Walking the shipped FST (`fst-global-priority.bin`) over the Paris
fixtures returns 43 distinct surfaces, and 37 of them would fire an emission bias:

| surface        | placetype : importance                  |
| -------------- | --------------------------------------- |
| `rue`          | localadmin 0.145, `neighbourhood` 0.149 |
| `boulevard`    | `neighbourhood` 0.167                   |
| `place`        | `neighbourhood` 0.169                   |
| `la`           | locality **0.850**                      |
| `du`           | region **0.650**                        |
| `londres`      | region 0.937, locality 0.936            |
| `saintgermain` | locality 0.386                          |
| `12`, `2`, …   | localadmin 0.05–0.15                    |

The French particles produce the strongest hits in the table. `la` scores 0.850 as a
locality inside street phrases like `Rue de la Paix`, and bare house numbers match
localadmin places. The conditions for the trap are present.

**The measured effect is zero.** Turning the prior on leaves the Paris target class
unchanged: 33/63 with it off and 33/63 with it on, with two fixtures changing in opposite
directions. The prior is therefore not what causes these addresses to fail today. The model
produces the locality reading on its own, because it learned from a corpus where bare
street fragments are rare and bare localities are common. The cause is the training
distribution, so the BAN corpus recipe takes priority over every inference-time change.

Keep the tier rule anyway. The rule follows from what the data encodes, and it does not depend
on a measured harm. A channel that answers "is this a locality" must never be read as answering "is this
a street," and a future consumer that did so would be reading the table above.

Tier C answers locality/region/country. It does not answer "is this a street."

### Tier D — licensing decides product use

OSM has the best coverage available for gap analysis and for experiments that need breadth.
Source quality, licensing, and attribution decide what can ship. `@mailwoman/osm` itself is
unpublished until ODbL counsel signs off.

## Training: phenomenon recipes

Each locale samples these recipes from its Tier A register:

1. **bare street** — `Rue Montmartre`
2. **street + particle** — `Rue de la Paix`, `Avenue des Champs-Élysées`
3. **street + house number**
4. **admin/street homonym** — the polarity class
5. **date-name** — `Rue du 11-Novembre-1918`
6. **alphanumeric house number**

**Recipe ratios stay capped** so that full-address performance does not regress. The cap
prevents the regression, and the regression guard on full addresses checks that it did. A
recipe that fixes fragments by degrading normal addresses has only moved the failure to
rows the fragment board does not score.

Label policy for street recipes: the **full street phrase** is labeled `street`, including
affix, particle, apostrophe, hyphenated compound, and date-name material.

## Eval: two boards, three questions

| Board                     | Question                    | Instrument                                                    |
| ------------------------- | --------------------------- | ------------------------------------------------------------- |
| **Global parity floor**   | Do no harm                  | `mailwoman eval parity` — broad, the standing floors          |
| **Locale fragment board** | Did the targeted class move | `mailwoman eval fragment-board` — per-class, Wilson intervals |

A change ships when board 1 stays at or above its floors **and** board 2 improves. Neither
board is sufficient on its own.

Two boards are needed for a concrete reason. The span-head work scored +23.8pp on its
target class and roughly +0 net overall. A single blended number would report that as
within noise, and it would hide both the +23.8pp gain and the classes that lost accuracy.
A 3/15 cell on a 63-row fixture has a 95% Wilson interval of 7–45%, which is too wide to
be useful. The fragment board samples BAN at ~400 rows per class, so each targeted class
gets a real error bar.

The first run of the board (v264, the shipped model) shows the kind of defect the board is
designed to catch. The streets and the model are the same in each class, and the only
difference is a leading number:

| class                             |   n |  rate | 95% CI         |
| --------------------------------- | --: | ----: | -------------- |
| street-housenumber                | 400 | 0.925 | [0.895, 0.947] |
| alnum-housenumber                 | 400 | 0.925 | [0.895, 0.947] |
| bare-street                       | 400 | 0.215 | [0.178, 0.258] |
| street-particle                   | 400 | 0.273 | [0.231, 0.318] |
| admin-street-homonym              | 400 | 0.087 | [0.064, 0.119] |
| date-name                         | 400 | 0.055 | [0.037, 0.082] |
| bare-locality _(emits no street)_ | 400 | 0.980 | [0.961, 0.990] |

**The house number accounts for the whole difference.** With a house number, the rate is
92.5%. Without one, it is 21.5%. The confidence intervals are far apart, so the difference
is clear.

### The third question: what does the board _not_ score?

Two boards turned out to be insufficient. Every street metric in the repo keeps only rows
that have a gold street label. A street **hallucinated on an input that has no street**
was therefore invisible to all of them: `New York, NY` → `street="new york"` could never
lose a point. The span decode failed in exactly the rows the filter dropped, so the metric
overstated that decode's accuracy **in particular**.

The fragment board therefore includes a **negative class**: `bare-locality` rows that
assert the parser emits _no_ street. A board that cannot score a failure cannot grade its
fix.

Apply this check generally. This work hit three measurement failures of this kind: starved
channels, a resolver without evidence, and a filtered corpus. Before trusting a board, ask
which rows it drops. A registered baseline does not prevent this. A baseline over a
filtered corpus stays self-consistent indefinitely. It guarantees reproducibility and says
nothing about validity.

## Why this holds

This work addresses three interacting causes: a training distribution that
underrepresents bare streets, an objective that rewards token correctness over useful
spans, and a resolver that has no evidence where a choice between readings is needed.
Registries address the first cause. They must not be used to hide the second or the third.
A parser turns into a dictionary one convenience at a time. Each step looks defensible on
its own until the hypothesis space is closed again and messy addresses fail.

The model resolves ambiguity, and registries only inform it.
