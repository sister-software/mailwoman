# The row count each recipe was asked for

A recipe emits the number of rows its `--count` flag names. The flag is required and carries no
default, so the number that decides how much of a country the corpus teaches lives in the command
that built it rather than in any committed file.

This page is that number, recovered by counting the rows of every recipe output on this machine's
data root on 2026-09-22. It exists because #2357 asked where a country's share of the corpus is set
and the repository held no answer.

## What this answers, and what it does not

**GB's 800,000 street rows are a `--count 800000`.** They are not a cap the reader imposes.
`RESERVOIR_CAP` in `packages/corpus/lib/international/recipes/locale.ts` is 1,200,000 and bounds the
pool held in memory while a source is streamed, which never binds a draw of 800,000. The four
largest locale outputs — ES pedanía, GB, NZ and the FR lieu-dit recipe — were each drawn at that
same 800,000, so the number is a convention rather than a per-country decision.

A row count recovered this way is the count the recipe emitted, which equals `--count` for a recipe
that reached its target. `synth-fr-lieudit-v1.jsonl` at 799,997 is three short of 800,000, so that
one either ran with a different flag or exhausted its pool.

**Where these numbers came from is still not recorded.** Counting an artifact recovers what a
recipe emitted. It does not recover the invocation, the seed, or the flags beside `--count`, and no
file on this machine carries them. A recipe output rebuilt from a different seed would count the
same and contain different rows.

## What records it from now on

`mailwoman corpus slice` writes `<out>.invocation.json` beside every recipe output, after the rows,
so a sidecar exists only beside a run that finished. It carries the recipe name, its mode, the rows
emitted and skipped, the time, and every option the run resolved:

```json
{
	"recipe": "locale",
	"mode": "generate",
	"emitted": 200,
	"skipped": 0,
	"read": null,
	"ranAt": "2026-09-22T06:10:56.983Z",
	"options": { "output": "…/lu.jsonl", "seed": 20260922, "variants": 1, "count": 200, "golden": false, "country": "LU" }
}
```

The recipe outputs listed above predate it and have no sidecar. The table is their only record, and
it goes stale the moment one of them is rebuilt.

## The five locales drawn for the v0.6.0 corpus

Each of these five ran with a sidecar, so the draw, the seed and the supply it drew from are all
recorded rather than recovered. The supply column counts the data rows of the country's
OpenAddresses `countrywide.csv`, measured 2026-09-22, and the pool column is what the reservoir held
when the draw was taken.

| country | supply rows | pool sampled | `--count` | emitted | skipped | city-noise drops |
| ------- | ----------: | -----------: | --------: | ------: | ------: | ---------------: |
| PT      |   5,911,139 |    1,200,000 |   800,000 | 800,000 |     332 |                0 |
| CH      |   2,759,181 |    1,200,000 |   500,000 | 500,000 |       9 |                0 |
| HR      |   1,680,503 |    1,200,000 |   300,000 | 300,000 |      27 |            1,003 |
| SK      |     219,728 |      219,728 |   150,000 | 150,000 |       0 |                0 |
| LU      |     164,415 |      164,415 |   150,000 | 150,000 |       0 |                0 |

All five ran at `--seed 20260922`.

Portugal's file holds 5,911,139 data rows and the recipe reported 5,667,574 reaching its reservoir
with 0 city-noise drops. What accounts for the 243,565-row difference is unmeasured; the supply
column states the file's own count.

PT, CH and HR each sampled 1,200,000 rows because `RESERVOIR_CAP` bounds the pool at that number and
each country supplies more. SK and LU supply fewer rows than the cap, so their pool is the whole
file and their draw is 68.3% and 91.2% of it. A country whose draw approaches its supply teaches
that country's addresses close to exhaustively, which is a different regime from PT's 13.5%.

Croatia's 1,003 city-noise drops are the only ones among the five. `cleanCityNoise` removes a row whose
city value contains a comma, and those rows are excluded from the 1,680,503 the reservoir saw.
