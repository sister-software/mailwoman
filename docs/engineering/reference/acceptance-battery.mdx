# The acceptance battery

The battery is the promotion use the v6→v8.2 arcs built run by run, packaged as one
procedure with two consumers:

1. **Our own promotes** — every candidate model (the v8.3.0 from-scratch retrain is the first
   consumer of the packaged form, and its exit criterion is this battery).
2. **A fine-tune engagement (B11)** — the same battery, instantiated per customer, run at
   delivery. The claim "Your fine-tune cannot break core parsing" means this
   battery passes at the calibrated EWC λ.

This page combines instruments documented elsewhere and adds a procedure and an engagement
instantiation. The contributor-facing promotion mechanics stay in
[Contributing model work](../CONTRIBUTING_MODEL_WORK.mdx) (the iron rules, the change taxonomy,
floor policy, the standard eval set); read that first if you're promoting a model yourself.

## The instrument inventory

| Instrument                                                         | What it guards                                                               | Where it lives                                                   |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Golden floors (per-locale, noise-aware margins)                    | the shipped baseline everywhere                                              | `mailwoman eval promote` + `mailwoman/eval-harness/specs/*.json` |
| P0 fragment boards **with lowercase legs**                         | the user register (lowercase is doctrine)                                    | eval-harness fragment boards                                     |
| Invariance suite vs the shipped reference                          | behavior unchanged against the shipped reference                             | `--baseline` legs of `mailwoman eval promote`                    |
| Gauntlet ×3 layers (incl. metamorphic INV/DIR)                     | input robustness: label-preserving perturbations mustn't move the coordinate | `mailwoman eval gauntlet`                                        |
| Evidence ablation (channels-zeroed ≥ baseline on unaffected spans) | the model mustn't launder capability through a retrieval channel             | in place since the v3.16 curriculum work                         |
| Ablated-vs-fed columns (per channel)                               | what each evidence channel contributes                                       | the capability manifest + the Modal per-channel contrast         |
| Canary fixtures with receipts                                      | recorded past failures stay fixed (zero-flip)                                | gauntlet fixtures (e.g. Fifth-Ave, world-city rotation)          |
| Presets byte-check + demo smoke                                    | the user-visible surface                                                     | `mailwoman eval preset-compare` + the demo smoke                 |
| Capability manifest (register-pinned)                              | the card's published capability block comes from a measurement               | `mailwoman eval capability-manifest`                             |
| Pre-ship gauntlet on the dev-linked flip                           | the exact bytes about to ship, through the exact runtime                     | the release choreography                                         |

Margins are **noise-aware**: `max(1.0pp, 2 × the metric's 95% binomial half-width)` at each
metric's support, taken from the reference model's own readings. Floors can rise when the reference
model is re-scored, and a promotion doesn't change them (see the floor policy in the contributor runbook).

## The procedure

1. **Pre-register.** The acceptance sheet — every bar, every baseline identity (model md5, tokenizer,
   lexicon versions, register) — is written into the run's config header or plan doc **before**
   any GPU spend. A number below a bar is a miss: re-baseline with a stated reason, or iterate. It
   doesn't pass. Every deviation from the sheet is recorded.
2. **Run the battery on the candidate artifact production will load**, the int8 export, through
   the ship-config channels. A scorer invoked without the declared channels grades a model missing
   those inputs, and a scorer with zero-filled channels has produced a wrong grade twice.
3. **Verdict.** PASS → ledger-append + the dated eval report. FAIL → the pre-registered
   contingency (a specified, single-delta fix and one re-run), then stop-and-report.

## Instantiate the battery for a fine-tune engagement (B11)

A customer engagement adds three things to the existing battery and leaves every other part unchanged:

1. **Customer canaries.** Golden rows drawn from the customer's own address stock (they nominate
   or we sample, and they confirm the gold labels). These become gauntlet fixtures with receipts —
   the customer-facing zero-flip set. Noise-aware margins need support: below ~200 rows per
   class, the margin is the binomial half-width and will be wide, and the report states that.
2. **The base-capability legs run unchanged.** The customer's fine-tune must hold every existing
   floor — the golden floors, the fragment boards, the gauntlet — within the noise-aware margins.
   Rare-class forgetting is structural to fine-tuning (the fr.cedex receipt), so the battery
   decides.
3. **The Fisher guarantee check.** The fine-tune trains with the base model's Fisher artifact
   (`fisher-diag-v1.npz`, shipped beside the base checkpoint) as an EWC brake at the calibrated λ
   (`train.ewc_lambda` / `ewc_fisher_path` / `ewc_reference`). The guarantee needs both: the EWC
   brake on parameters and this battery on behavior. Neither one is the guarantee by itself. A
   battery failure at the calibrated λ is a finding about the customer data, reported before
   delivery.

λ calibration happens once, on our own next fine-tune: sweep λ ∈ {0, 1e2, 1e4, 1e6} on a 2k-step
probe, keep the largest λ that leaves the increment's target metric within noise of λ=0. That λ
is the template default. An engagement inherits it and revisits only on a battery failure.
