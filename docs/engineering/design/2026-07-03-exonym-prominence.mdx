# Exonym prominence in the exact tier

**Status: design note for review (2026-07-03). This note has not been implemented. The concrete
failing row is the `global-abo-alias` gauntlet case (tracked as `improvement_target`, #912).**

## The tension, made concrete

The exact-tier sub-tier from #927 ranks a name-exact candidate above an alias-exact candidate. A
candidate is name-exact when the query equals the place's own `spr.name`, and alias-exact when the
query matches only an alias. Population orders candidates within each sub-tier. This rule fixed the
_Paris Township_ class of errors, where an alias tied with the primary name.

The v5.2.0 Nordic splice then fixed the tokenization of "Åbo", so the exonym now parses as one token.
That change exposed the sub-tier's known tradeoff on a real row. Unscoped **"Åbo" now resolves 859 km
away** to a tiny place whose primary name is Åbo (name-exact). The correct answer is Turku
(population 207k), which holds "Åbo" only as an alias in our gazetteer. Before #927, ranking by
population within one tier let Turku win. The sub-tier is more principled in general, but it gets
this row wrong.

A naive fix could break two cases that must keep working. `ME → Maine` is alias-exact and has no
name-exact competitor. `Paris → Paris, France` is name-exact and correctly beats a more populous
alias holder.

## Why "Åbo" is not an alias

Finland is officially bilingual. "Åbo" is Turku's **official Swedish name**, in the same class as
Karjaa/Karis, which the #743 bilingual-recall fix already treats as first-class names on ingest. Our
gazetteer stores one primary name (`spr.name` = "Turku") and demotes every other official-language
name into the alias bag. The sub-tier's ordering is correct. The defect is that **the name-exact test
consults only a single primary name, although places like Turku have official names in more than
one language.**

## The rule space

1. **Population-ratio override**: alias-exact may outrank name-exact when
   `pop(alias holder) / pop(name holder) > K`. This option is rejected as the primary rule. K is an
   arbitrary constant without a principled value. It would reintroduce the imprecise cross-tier
   population comparisons that #927 removed, and it would bring back the Paris Township error for
   extreme ratios.
2. **Curated exonym table**: a provenance-tracked exonym→canonical dataset consulted at rank time.
   This option is workable but heavy. It adds a new data artifact and maintenance burden for
   information the gazetteer's `names` table already encodes (language-tagged names with WOF
   provenance). A hand-grown table would also go against the project's rule against irrelevant
   trivia.
3. **Official-language names are names** _(recommended)_: widen the name-exact sub-tier's
   definition from `spr.name` to "any official-language name of the place". These are the
   language-tagged name rows the gazetteer already carries, such as `name_swe` for Turku in WOF.
   Alias-exact remains the tier for abbreviations, colloquialisms, and historical forms. Turku
   becomes name-exact for "Åbo" and beats the hamlet on population _within_ the sub-tier. Paris
   Township stays alias-exact, because its "Paris" is a truncation rather than an official name in
   another language. `ME → Maine` is unchanged, because abbreviations stay in the alias tier and it
   has no name-exact competitor.

## What option 3 needs (scoping rather than commitment)

- Ingest: mark official-language name rows separately from alternate and colloquial names. WOF's
  `name_*` language tags and `official` flags carry this information. The candidate and FTS builders
  would store one extra bit per name row.
- Lookup: the exact-tier classifier consults `names WHERE official = 1` for the name-exact test. This
  is one indexed probe, with the same shape as today's alias check.
- Check: run the bare-namesake gauntlet rows (Paris/Dublin/Melbourne/Vancouver/Åbo plus the ME/NY
  abbreviations), US-2k ni, and the quad panel ni set. This is the same battery #927 ran, and the Åbo
  row is expected to flip to conditional.
- Risk probe (run on 2026-07-03): 6,910 names are shared by two or more localities above 100k
  population. That count is an upper bound across all name classes, because today's `names` table
  cannot distinguish official-language rows from transliterations and colloquialisms ("A-shih-ko"
  counts the same as "Åbo"). The official-only subset is likely far smaller, but it cannot be
  measured until the ingest bit exists. Option 3's ingest work is therefore a prerequisite for its
  own risk assessment. The proposed order is: add the ingest bit, re-run this probe on official
  names only, and then decide on the lookup change.

## Decision requested

Approve option 3 for a scoped implementation pass (ingest bit, lookup probe, and the #927 battery),
or defer it until after the v2.2.0 retrain evaluation.
