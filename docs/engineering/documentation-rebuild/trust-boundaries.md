## Provenance path and losses

1. The address-source register (`packages/corpus/data/address-source-register.json`, typed in `packages/corpus/lib/source-register/types.ts`) assigns a stable `sourceID`, publication and publisher fields, research state, upstream lineage where known, license decision, and personal-data review. A corpus adapter emits its own source ID in the row's `source` field. A register source ID and a geocoder's coordinate source string are separate namespaces.
2. The corpus and effective training manifest record sources admitted to model training. The weights package's model card and provenance file identify a published model and its training lineage. Inference doesn't expose which training rows affected a particular prediction.
3. A geographic layer's `layer_manifest` can record source vintage, source URL and digest, build command and commit, license, attribution, and source counts. `packages/mailwoman/lib/data/catalog/inventory.ts` distinguishes manifested, unprovenanced, foreign, and unreadable local databases. `packages/mailwoman/lib/data/terms/bom.ts` distinguishes a license read from an artifact manifest from an expression assigned by the bundle registry. An unmeasured component stays unmeasured.
4. The resolver uses the installed geographic database to select a place or address row (`packages/resolver/lib/resolve.ts` and its street tier). The response's `candidates` retains the selected place and the places each resolved span passed over, deduplicated by place ID. The projection omits some database rows probed and transformations applied. Resolver trace events are available only when a caller supplies a trace sink.
5. The result extractor (`packages/mailwoman/lib/geocode/result.ts`) chooses the coordinate tier. It copies `coordinate_source` only when an address-point or interpolation row has a nonempty string source, or on the landmark venue branch. Its release is null when the row or landmark supplies none. Other tiers, and a later move away from a row's coordinate, have null `coordinate_source`. A null stamp must remain unknown provenance at the response level rather than an assertion of no source.

The available records do not establish the freshness of every source row, a full candidate-to-publication chain, removal of a withdrawn source from already distributed weights or databases, or bit-for-bit replay of every request. A future audit needs the exact input, request options, package and model digests, selected database digests, runtime settings, resolver trace if captured, and expected output. Those inputs can contain private addresses and sensitive source identities.

## Threats and falsifiable checks

The operator controls its deployment and local data root. This table assumes the repository's released code is trusted for the stated check. An external publisher may supply false data, a distributor may substitute files, and a caller or consumer may alter requests or responses. Each mitigation is scoped to what the inspected code records.

| Threat and adversary capability                                            | Recorded mitigation                                                                                                           | Residual risk                                                                                                         | Acceptance test before a stronger claim                                                                                                                                  |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A publisher supplies an incorrect or stale address observation.            | Source and vintage can be recorded in `layer_manifest`. A row may record a source stamp.                                      | Recorded vintage can be absent or old, and a correctly copied row can be wrong.                                       | Compare exact rows listed by source ID and row ID with a dated independent authority. Report errors over the sampled rows and by source.                                 |
| A distributor substitutes a different database or weights file.            | Package versions, model card, artifact manifest and published size snapshot identify some expected files.                     | A version label or MD5 sidecar doesn't establish publisher authenticity. Local files can differ from published files. | Pin a SHA-256 digest for each selected file and verify it before use against a trusted publication channel.                                                              |
| A builder changes an ingestion transform or omits source rows.             | Source register, build command and build SHA fields, and data bill of materials provide audit inputs.                         | A manifest can be incomplete or false. Downstream output may lose row lineage.                                        | Rebuild the source snapshot identified by publisher and vintage with the recorded command and commit, compare normalized row counts and digests, and inspect mismatches. |
| A caller changes request context or a consumer edits the response.         | The response can retain input, selected tier and candidates. An optional resolver trace captures events.                      | The standard response has no authenticated request or response signature.                                             | Capture request bytes and options at the trusted boundary and compare their digests with an authenticated response record.                                               |
| A result attributes a coordinate to the wrong publisher.                   | The result copies the source from a stamped address row. Its tier identifies the mechanism that selected the coordinate.      | A source string may name a transformed artifact and cannot prove the upstream publication.                            | For sampled selected rows, join the output stamp to artifact row, build input, and original publication. Count unresolved joins.                                         |
| An operator trains on, redistributes, or discloses restricted source data. | The source register has operation-specific license decisions and personal-data review. Bundle rights record unresolved terms. | A recorded decision cannot enforce an external agreement or retract distributed derivatives.                          | For each admitted source, compare granted purposes with actual pipeline stages and emitted artifacts. Refuse any purpose without a recorded grant.                       |

Authenticity concerns who issued a record. Integrity concerns whether its bytes changed. Freshness concerns whether its observation is recent enough for a stated use. Accuracy compares the result with an independent expectation. Precision describes the coordinate's spatial specificity. Authorization concerns whether a use is permitted. Availability concerns whether the service and data can be accessed. None of those properties follows automatically from another.

## Optional evidence receipt proposal

This is a design proposal. It changes no public API. A separate implementation issue needs an owner, privacy review, and acceptance tests before code is added.

The smallest useful receipt would record a schema version and a keyed request fingerprint instead of raw private input by default. It would identify the runtime package, decoder and model digest, selected database version and SHA-256 digest. It would copy the result's tier, status, uncertainty, and coordinate source exactly as returned. The receipt could include collected resolver events and candidate identities when available. It would record why any value is unavailable. It would identify the producer and capture time. An integrity signature, if added, would authenticate those receipt bytes against an identified key. It wouldn't certify the source observation or coordinate as correct.

Do not emit candidate rows or original addresses to an external receipt store by default. A source agreement may prohibit source IDs or coordinates in an external log. Retention duration and access controls require a source-specific decision. Measure serialized bytes per request, added latency over the same requests without the receipt, replay agreement under an unchanged model and data snapshot, and changes after either snapshot changes. Report sample count, baseline, comparison arm, and failures. Deterministic replay of a recorded execution is separate from explaining why a neural model assigned a label.

## Contributor permission contract proposal

The current source register separates fetch, extract, transform, train, data redistribution, model redistribution, and commercial sublicense. A data-holder agreement also needs explicit answers for the following purposes. This proposed matrix needs owner review. The current product doesn't enforce these purpose grants.

| Purpose             | Permission to record per source                                                                     | Operational control to specify                                                                                 | Disclosure boundary                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Model training      | May source rows or derived labels fit weights? May weights be distributed or sublicensed?           | Corpus snapshot identified by version and digest, deletion window for retained raw rows, and refresh schedule. | Whether training-source names, examples, and resulting weights may leave the operator. |
| Gazetteer retrieval | May records be indexed and queried? May the index be shipped?                                       | Authorized users, allowed query purposes, local retention, and source refresh.                                 | Whether a matched row, source ID, or coordinate may appear in a response.              |
| Internal validation | May rows serve as expected answers or audit samples?                                                | Evaluator access, retention, sampling, and isolation from training.                                            | Whether aggregate metrics or exact examples may be published.                          |
| External disclosure | May raw rows, identifiers, derived coordinates, or conclusions be shown to customers or the public? | Redaction, aggregation, attribution, audit log, and downstream-use conditions.                                 | Distinguish a visible result from a downloadable source database.                      |

For each purpose, the agreement needs the legal entity that signs it, source and version, permitted use, territorial or sector restriction, redistribution and derivative terms, attribution text, retention period, refresh frequency, audit access, withdrawal procedure, and contact for disputes. The owner must separate what an agreement promises from controls that the software enforces. An operator can stop future retrieval by deleting a local source file and rebuilding its indexes. The operator cannot retroactively recall results already sent or weights already distributed. A withdrawal request therefore needs a dated inventory of affected artifacts, a stop-use plan, and a statement of what cannot be recalled.

**Public authoritative register scenario.** A government publisher may permit retrieval and redistribution with attribution but restrict the publication of personal records or require a current-vintage notice. Record each of the four purposes independently. Test the exact publication and terms against the built artifact. Publication at a public URL doesn't grant model-training or unrestricted disclosure rights.

**Restricted commercial database scenario.** A provider may permit local retrieval for a specified customer workflow while refusing training, redistribution, and raw-record disclosure. Keep its index local to authorized operators. Prevent source rows and IDs from entering public logs and example receipts. Use a separate validation set only if the agreement grants that use. If the current product cannot enforce the required isolation or deletion, reject the source for that workflow until the controls exist and are tested.

## Reviews and artifact checks still required

- A designated rights owner must approve public interpretations of `candidate`, `poi`, `fr`, `us`, and any new contributor contract against the exact source and intended use. The product page records the unresolved questions.
- After the geographic-data rebuild, name the artifact and digest, inspect its manifest and source rows, run a full geocode example with an exact address that may be published, and record the response and command. Check null and stamped `coordinate_source` cases. Compare any expected coordinate with an independent source.
- After the separate training run, update model-quality and benchmark claims only from its registered evaluation and release verdict. The current record supplies no new score.
