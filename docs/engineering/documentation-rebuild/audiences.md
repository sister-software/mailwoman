# Documentation audiences and evidence

This plan describes readers of the public Mailwoman site. It is a planning decision for the clean-sheet documentation rebuild in [issue #2979](https://github.com/sister-software/mailwoman/issues/2979). The pre-cutover site and a dated audience review provide evidence about intended readers. They do not measure actual traffic, support demand, or task completion. The [pre-cutover articles](https://github.com/sister-software/mailwoman/tree/v11.0.0/docs/articles) are preserved in the `v11.0.0` Git tag.

## Reader and task decisions

| Reader                                    | Evidence status                                                                                       | Entry question                                                                                 | First successful result                                                                                            | Appropriate next page                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| Developer evaluating the library          | Inferred from the product overview, installation pages, and library reference                         | Can this package parse my input in my runtime?                                                 | Runs one versioned parse example and identifies the returned component shape.                                      | Library API reference or parse-result explanation.             |
| Developer integrating geocoding           | Inferred from the geocoding guides, tutorials, and HTTP reference                                     | What local data must I install, and what precision can I claim?                                | Resolves one address and reads its tier and provenance.                                                            | Data setup guide, resolution reference, or benchmark evidence. |
| Operator deploying a service              | Inferred from Docker, serverless, data refresh, and migration pages                                   | How do I run and maintain this with known resource limits?                                     | Starts a service and checks installed data and health.                                                             | Deployment and data operations guides.                         |
| Analyst cleaning address records          | Inferred from validation, matching, batch geocoding, and CSV pages                                    | How do I process a file and interpret incomplete or ambiguous results?                         | Produces a reviewed output file with explicit unresolved rows.                                                     | Batch, validation, or matching guide.                          |
| Technical evaluator or procurement reader | Inferred from solution, comparison, license, footprint, and benchmark pages                           | What does the product do, what does it cost to operate, and what evidence supports its claims? | Finds dated capability, limitation, license, footprint, and benchmark statements in one route sequence.            | Product status and evidence pages.                             |
| Researcher or contributor                 | Observed as an intended audience in the 2026-05-25 review and current research/engineering navigation | How does the parser work, and how are claims evaluated?                                        | Reaches architecture explanation and evaluation methods without mistaking historical records for current behavior. | Corpus, model, decoder, and release-quality explanations.      |

These reader groups can overlap. Pages should be organized by the reader's immediate task and the Diátaxis purpose of the page. A deployment operator can need a tutorial while learning and a guide while carrying out production work.

## Scope and acceptance questions

The new public documentation serves the library, command-line program, HTTP server, data layers, and documented browser and agent integrations. Product and solution pages remain outside the technical sidebar. Historical engineering records remain dated records. The rebuild does not treat each of the 82 existing article pages as a required destination.

Review each proposed page brief against one concrete question: What can this reader do or understand after this page that the neighboring page does not provide? During implementation, record the release version and command output for executable examples. Attach a source and date to numerical claims. Have a reader from the relevant group attempt the task. And record where that attempt stops. Those checks will turn the inferred audience map into measured evidence.
