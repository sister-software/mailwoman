# Page briefs for the new public site

These briefs define proposed reader results and their acceptance checks. IDs and routes come from `information-architecture.md`. The writer must confirm every current command, package, output shape, footprint, supported locale, and numerical claim against the release being documented. Old article text is source material with an unverified factual status. Each page has one primary reader result, a role, source leads, and a check that can fail.

## Draft and review sequence

1. Confirm the reader question and the page role. The proposed role can change if a task exercise reveals a different need.
2. Check `source-to-target.md` for old sections and old URLs. Extract facts into a claim list before writing new prose.
3. Check each command against the owning code or released artifact. Check each measurement against its dated data source or executed example. Mark unsupported claims for omission or a labeled open question.
4. Draft from a role template in `docs/engineering/page-templates/`. Use Good Docs prompts only where they serve the reader's task. Define terms on first use and follow `docs/engineering/writing-system.md`.
5. Run the page's commands, inspect rendered output and links, and ask a reader in the target group to attempt the result. Record version, platform, data, and date.
6. Publish the replacement route and its redirects together. Check inbound old links and the old section anchors before retiring the source page.
