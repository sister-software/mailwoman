## What this is trying to do

Build a provenanced crosswalk of US broadband carrier identity: FRN ↔ Form 499 filer ID ↔ SEC CIK ↔
corporate family, so a question like "who actually owns the carrier serving this address, and when did
that become true" has a documented answer with a citation.

The hard part was never the schema. It is that the join keys are **company names**, and the names are
free text, inconsistently cased, decades stale, and sometimes misspelled in the source. Nexus (the
predecessor project, `/home/lab/Projects/isp-nexus`) got as far as it did on domain knowledge and
stopped at record matching. Mailwoman's parser and `@mailwoman/record`'s `canonicalizeOrganizationName`
are what make it mechanical.

Measured on the Form 499 filer database, which sizes the problem:

|                                                   |                                 |
| ------------------------------------------------- | ------------------------------: |
| filers                                            |                          19,852 |
| carrying a 10-digit FRN                           |                  18,953 (95.5%) |
| naming a holding company                          |                   5,942 (29.9%) |
| distinct holding-company strings                  | 3,341 raw → **2,933 canonical** |
| canonical parents that are themselves a 499 filer |               1,339 (**45.7%**) |
| rows carrying a lifecycle note                    |                  11,533 (58.1%) |

The two numbers that matter: **12% of holding-company strings are pure spelling variance** that
canonicalization collapses for free, and **54% of named parents never file a Form 499 at all** — they
are holdcos, PE vehicles and foreign parents. That second half is the gap SEC EDGAR Exhibit 21 fills,
because the parent that is absent from the FCC file often files with the SEC.

## Doctrine — read before writing any code

These are not style preferences. Several of them were arrived at after a defect shipped.

1. **Documented relationships only.** Every edge must trace to a document that states it. No inference
   from co-location, shared contacts, or similar names.
2. **Disclosure, never accusation.** Never assert intent or wrongdoing about a named company. Where a
   source states something adverse (a bankruptcy note, say), it is carried as a quoted record with
   provenance, never as a status this project derives. See `Form499CessationReason.Bankruptcy`.
3. **Absence is not impossibility.** A missing record means the source did not say, not that the fact is
   false. Abstentions are counted, never converted into a default.
4. **Abstain, never guess.** A row that cannot be confidently reduced is counted and dropped. This is
   "decision 6" in the older docs.
5. **Provenance on every edge** — source, vintage, and the temporal window it holds over.
6. **Never keyword-sniff.** Match whole strings against closed vocabularies. `includes("CITY")` →
   municipal makes "Kansas City Telephone" a municipality; `includes("subsidiary")` misfires on a
   company named that. Both are real bugs found in inherited code.
7. **An abstention must never look like a record.** The Nexus CORES client returned a fabricated
   `Organization` with `registeredAt: new Date(0)` when a fetch failed. That is the single worst pattern
   in the inherited codebase — it manufactures data that reads as fact.

### Testing norm, and it is enforced socially rather than by a linter

**Ground truth must not come from the implementation under test.** A fixture expectation generated by
running the parser records whatever the parser does, defects included. Earlier in this project a fully
green fixture suite sat on top of a parser that produced 45 subsidiaries where the documents stated
2,640 and fabricated 18 names. `filer/test-fixtures/edgar/expected.json` is therefore derived from an
independent implementation in another language (`reference-oracle.py`) and hand-checked.

When you add a rule, **mutation-verify it**: break the rule deliberately, confirm the test fails, restore.
A test that passes both ways is not a test. Every rule landed on this branch was checked this way, and
the check caught a real one (`recaseUniform` keyed on the wrong thing).

`filer/sdk/sec-client.ts`: an `APIClient` subclass, exact-match host allowlist, strict-interval pacer,
disk cache, bounded retry, and a one-method `CORESDocumentClient` seam so no test touches the network.

- **Endpoint:** `https://apps.fcc.gov/cores/searchDetail.do?frn=<frn>` — HTML, 200, no auth, ordinary
  descriptive User-Agent. Verified live 2026-08-07.
- **`data.fcc.gov/api/frn/getInfo` is 403** at the Akamai edge from this host and a User-Agent does not
  change it. Do not retry it hoping; it is host/IP-based.
- **The HTML page carries no parent/subsidiary fields.** An older plan claims CORES is a family-edge
  source — that claim was about the JSON API and is wrong for this page. CORES is corroboration only.
- Paced at 4 req/s. CORES publishes no rate limit; that is a reason for restraint, not licence.

### `filer/sdk/form499-notes.ts`

`isCeasedFiler` is deliberately narrow — false for exited-telecom and account-consolidated, because

claims, and nothing consumes them yet.

## Traps that cost real time. Each of these fails silently.

1. **`normalizeColumnNames` leaves ALL-CAPS headers alone by design.** The FRN column key is `CORESID`,
   **not** `coresid`. Reading the lower-cased spelling yields `undefined` on every row and every filer
   loses its FRN, with a successful-looking parse.
2. **`DC_Agent_EMail` normalizes to `dc_agent_e_mail`**, not `dc_agent_email` — the inner capital M is a
   word boundary to the snake-caser. Caught only because `assertWorkbookHeader` exists.
3. **`LastFiling` is `M/D/YYYY`.** It becomes `valid_from`; `assertISODate` throws on it, and
   `build-filer.ts:610` picks the latest legal name per FRN by **plain string comparison**, where
   `4/1/2025` sorts below `12/31/2018`. Converted once in the reader.
4. **`USF_Contributor_1` is `Yes`/`No`**, but `Form499Row.usfContributor` is documented as true iff the
   raw value is the literal `TRUE`. A pass-through makes every filer a non-contributor.
5. **`company_tickers.json` only covers registrants with a ticker** — 10,398 rows, 7,998 distinct CIKs.
   It contains **none** of Cellco Partnership (the largest holding company in the 499 file, 125 filers),
   Windstream, Zayo, Brightspeed, Consolidated, Hargray, Altice or Metropolitan Telecom. This sector is
   majority private-equity-owned. Use `https://www.sec.gov/Archives/edgar/cik-lookup-data.txt`
   (1,054,085 entries, 40 MB, public, no auth) instead — and note the haystack is 130× bigger, so
   name-only matching gets **more** dangerous, not less.

## Open tasks, in dependency order

### 1. `filer.db` schema change — supersession edges and `valid_to`

Currently `filer/schema.ts` has:

```ts
export const FilerRelationship = {
	SameEntity: "same_entity",
	HoldingCompany: "holding_company",
	ManagementCompany: "management_company",
	ParentCompany: "parent_company",
	Subsidiary: "subsidiary",
} as const
```

Add a supersession member (`Superseded`/`SupersededBy` — pick one direction and document it). Then:

- `Form499Lifecycle.ceasedAt` → `valid_to` on that filer's edges. Nothing sets `valid_to` today, so
  every ceased carrier currently reads as open-ended.
- `Form499Lifecycle.replacedByForm499ID` → an edge to the successor filer's node.
- Bump `FILER_FAMILY_SCHEMA_VERSION` (currently `2`, in `filer/schema.ts:324`). `@mailwoman/filer` is
  published on npm at v9.x, so this is a real versioned change with a consumer rebuild — the "nothing
  has shipped yet, columns are free" argument from earlier phases is spent.

**Adding a `FilerRelationship` member will fail to compile** until `OWNERSHIP_BY_RELATIONSHIP` in
`filer/tools/linkage-eval.ts:173` is updated — it is pinned `satisfies Record<FilerRelationship, boolean>`
precisely so a new class cannot silently fall through to "counts as ownership". That is the pin working.
**Ruling needed: does supersession assert ownership?** My recommendation is **no** — it is identity
continuity, not control — so pin it `false`. Ask the operator if unsure; it changes an eval's score.

### 2. SIC corroboration gate

Name-only CIK resolution produced **2 confidently wrong registrants out of 24** on a real run: "Altice
USA, Inc." → AlTi Global, Inc. at 0.829, and "WideOpenWest, Inc." → WidePoint Corp at 0.886. Both are
vendored under their true names in `filer/test-fixtures/edgar/` as evidence.

A SIC gate on 48xx (Communications) is 2-for-2 at rejecting those, and 6-for-8 at keeping real carriers.
Measured live:

```
AlTi Global      6282  Investment Advice                 rejected ✓  (the false Altice match)
WidePoint        7373  Computer Integrated Systems       rejected ✓  (the false WideOpenWest match)
Lumen · Anterix · IDT     4813                           accepted
Cable One · Liberty Bb    4841                           accepted
Gogo                      4899                           accepted
Bandwidth        7372  Prepackaged Software              rejected ✗  ← a real CLEC
Ooma             7374  Computer Processing               rejected ✗  ← a real VoIP carrier
```

SIC comes from the submissions payload (`https://data.sec.gov/submissions/CIK##########.json`, field
`sic`). Pair the gate with an **operator-pinned CIK list** for the 737x-classified carriers — a pin is
documented and auditable, which widening the allowlist until the false matches creep back is not.

Worth checking first: whether EDGAR's bulk `submissions.zip` gives SIC for every registrant in one
download, which would replace one request per candidate. See
`https://www.sec.gov/search-filings/edgar-application-programming-interfaces`.

### 3. The orchestrator

Produce `EdgarSubsidiaryRow`s (`filer/sdk/build-filer.ts:216`) and feed `buildFilerDatabase`'s existing
`edgarRows` option. The chain pieces all exist and are tested:

```
cik-lookup-data.txt  →  resolveCIKCandidates      (edgar-filings.ts, share-class collapse landed)
                     →  SIC gate + pins           (TASK 2 — not built)
  fetchTenKFilings   →  findExhibit21Documents    (edgar-filings.ts, landed)
                     →  fetchExhibit21 / parseExhibit21  (exhibit21.ts, landed, measured on 21 real filings)
                     →  EdgarSubsidiaryRow[]      (TASK 3 — not built)
```

`resolveCIKCandidates` deliberately returns **every** candidate above a threshold, never a single
winner, and reports a genuine tie in full even at `limit: 1`. Do not "fix" that into a single pick — it
is the guard against exactly the two false matches above.

Tools live in `filer/tools/` as library modules with no argv and no `process.exit`; the command owns

## Repo conventions you will trip on

- **Verify before claiming.** Run the command, paste the output. "Tests pass" without the run is the one
  thing that will get your work distrusted here.
- `yarn vitest run filer/` · `yarn typecheck:tests` (needs `yarn compile` once per worktree) ·
  `yarn lint:oxlint` · `yarn oxfmt <files>`. A pre-commit hook runs format and lint.
- **`yarn typecheck:tests` is not optional.** `satisfies` pins in test files are invisible to both vitest
  and `tsc -b`; that check is the only thing that sees them.
- No `enum` — `erasableSyntaxOnly` is on repo-wide. Use a const object plus a derived type.
- Acronyms are whole identifier components: `CIK`, `SEC`, `FRN`, `HTML`, `URL`, `SGML`.
- Tabs, double quotes, no semicolons. Match the surrounding file.
- `@mailwoman/filer` has no HTML-parser dependency and should not gain one. `exhibit21.ts` exports
  `stripTags` / `decodeEntities` / `normalizeWhitespace`; reuse them rather than adding a second
  normalizer.
- Work in a git worktree under `.claude/worktrees/`, not the main checkout. The git stash stack is shared
  across worktrees and other sessions may be using it — prefer a WIP commit to `git stash`.
- Docstrings here carry the _why_, especially the rejected alternative. A comment explaining what a line
  does is noise; one explaining what it prevents is the point.
